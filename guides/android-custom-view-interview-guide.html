01 · ROADMAP

先抓住四条主线

自定义 View 不是孤立 API 集合。把属性、尺寸、像素和事件四条线串起来，绝大多数面试追问都能顺着回答。

1

属性输入

构造函数、AttributeSet、style 和状态。

2

尺寸位置

MeasureSpec、onMeasure、layout。

3

像素输出

Canvas、Paint、文字与性能。

4

用户输入

分发、拦截、手势和冲突。

构造/属性→measure→layout→draw→touch/animation
答题模板：一句话结论 → 调用流程 → 关键边界 → Android 实战例子 → 常见坑。不要一上来背源码方法名。
02 · BASICS

构造、属性与选型

先回答为什么要自定义，再说明 XML 属性如何进入 View。很多候选人会画，却说不清样式优先级和状态更新。

Q01

自定义 View 有哪几种实现方式？

★★★★★

继承 View 自绘、继承现有控件扩展、继承 ViewGroup 自定义布局、组合多个现有 View。选型原则是：能组合不自绘，能扩展现有控件不从零实现。

继承 View仪表盘、波形、进度环等像素级绘制。
继承 ViewGroup流式布局、特殊堆叠和自定义摆放策略。
追问：为什么组合优先？因为焦点、无障碍、状态、主题和事件行为更容易复用系统实现。
Q02

四个构造函数分别有什么作用？

★★★★★

一参用于代码创建，二参用于 XML，三参加入主题默认属性，四参再加入默认 style 资源。Kotlin 常用 @JvmOverloads 暴露前三种调用。

class GaugeView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = R.attr.gaugeViewStyle
) : View(context, attrs, defStyleAttr)
如果忽略 defStyleAttr，主题中的组件默认样式可能不生效。
Q03

如何定义并读取自定义属性？

★★★★★

在 attrs.xml 中声明 declare-styleable，通过 obtainStyledAttributes 合并 XML、style、主题默认值，读取完必须 recycle。

val a = context.obtainStyledAttributes(
    attrs, R.styleable.GaugeView,
    defStyleAttr, R.style.Widget_App_GaugeView
)
try {
    color = a.getColor(R.styleable.GaugeView_gaugeColor, Color.BLUE)
    strokePx = a.getDimension(R.styleable.GaugeView_gaugeStroke, 8f)
} finally {
    a.recycle()
}
dimension 读出后已经是 px；不要再重复乘 density。
Q04

属性变化后调用 invalidate 还是 requestLayout？

★★★★★

只影响像素外观调用 invalidate；可能改变期望宽高或子 View 位置时调用 requestLayout，通常再 invalidate。

var progress: Int = 0
    set(value) {
        field = value.coerceIn(0, 100)
        invalidate()
    }

var labelSizePx: Float = 40f
    set(value) {
        field = value
        requestLayout()
        invalidate()
    }
03 · LIFECYCLE

View 工作流程与生命周期

面试官不要求死背整棵 ViewRootImpl 调用栈，但要能说清一次 traversal 如何走完，以及哪些回调可能重复发生。

Q05

View 的测量、布局、绘制流程是什么？

★★★★★

ViewRootImpl 在一次遍历中驱动 performMeasure、performLayout、performDraw，递归调用 View 树的 measure、layout、draw。

scheduleTraversals→measure→layout→draw
标准回答：measure 确定 measured size，layout 确定四个边界，draw 把最终状态绘制到显示管线。
Q06

draw() 和 onDraw() 有什么区别？

★★★★★

draw 负责完整绘制编排；onDraw 只负责 View 自身内容。通常重写 onDraw，不轻易接管 draw。

背景→onDraw→dispatchDraw→前景/滚动条
改变 draw 顺序时还要考虑背景、子 View、foreground、clip 和硬件加速。
Q07

onSizeChanged() 适合做什么？

★★★

在尺寸真正变化后，根据新宽高重新计算 RectF、Path、渐变、刻度位置等几何缓存，比每帧在 onDraw 中计算更合适。

override fun onSizeChanged(w: Int, h: Int, oldw: Int, oldh: Int) {
    contentRect.set(
        paddingLeft.toFloat(), paddingTop.toFloat(),
        (w - paddingRight).toFloat(), (h - paddingBottom).toFloat()
    )
}
Q08

onAttachedToWindow 和 onDetachedFromWindow 如何使用？

★★★

attach 时注册窗口相关监听或恢复任务；detach 时取消动画、Runnable、监听和资源。detach 表示离开窗口，不等于对象立即销毁。

长期 post 的 Runnable、Animator 或外部监听如果不清理，可能继续持有 View 和 Activity。
04 · MEASURE & LAYOUT

测量与布局

这是自定义 View 最常问的部分。必须会解释 MeasureSpec 三种模式、wrap_content、padding，以及 ViewGroup 如何测量子 View。

Q09

MeasureSpec 是什么？

★★★★★

它把父容器传下来的约束编码为 mode 和 size。EXACTLY 表示确定尺寸，AT_MOST 表示上限，UNSPECIFIED 表示父容器不设边界。

模式含义常见来源
EXACTLY必须使用给定尺寸固定值、很多 match_parent 情况
AT_MOST不能超过 sizewrap_content
UNSPECIFIED不限制特殊父容器/内部测量
Q10

自定义 View 如何正确支持 wrap_content？

★★★★★

计算内容期望尺寸，加上 padding 和最小尺寸，再用 resolveSizeAndState 或 resolveSize 与父约束合并，最后 setMeasuredDimension。

override fun onMeasure(widthSpec: Int, heightSpec: Int) {
    val desiredW = contentWidth + paddingLeft + paddingRight
    val desiredH = contentHeight + paddingTop + paddingBottom
    val w = resolveSizeAndState(maxOf(desiredW, suggestedMinimumWidth), widthSpec, 0)
    val h = resolveSizeAndState(maxOf(desiredH, suggestedMinimumHeight), heightSpec, 0)
    setMeasuredDimension(w, h)
}
不要无条件把 MeasureSpec.size 当成自己的尺寸，否则 AT_MOST 下的 wrap_content 会占满上限。
Q11

measuredWidth、width 和 layoutParams.width 有何区别？

★★★★★

measuredWidth 是测量结果；width 是 layout 后 right-left；layoutParams.width 是布局意图，可能是具体值、MATCH_PARENT 或 WRAP_CONTENT。

测量结果不必等于最终布局尺寸，父容器仍可能用不同边界调用 layout。
Q12

为什么 onMeasure 可能执行多次？

★★★

父容器可能多轮试探约束，例如 weight、复杂父布局、重新分配剩余空间或 requestLayout。onMeasure 必须幂等、快速，不能假设只执行一次。

不要在 onMeasure 发网络请求、创建大 Bitmap 或启动动画。
Q13

requestLayout 和 invalidate 的区别？

★★★★★

requestLayout 请求重新测量布局；invalidate 标记区域需要重绘。尺寸变化走前者，纯颜色/进度变化走后者。

requestLayout 最终是否立即触发 traversal 取决于父链和调度；它不是同步完成测量。
Q14

如何正确处理 padding 和最小尺寸？

★★★

测量时把左右/上下 padding 加入期望尺寸；绘制时内容区从 padding 起算；再通过 suggestedMinimumWidth/Height 尊重 minimumWidth、背景最小尺寸等约束。

Q15

ViewGroup 如何测量子 View？

★★★

根据自身 MeasureSpec、padding、已用空间和子 LayoutParams 生成 child specs，再调用 measureChild、measureChildWithMargins 或 child.measure。

for (i in 0 until childCount) {
    val child = getChildAt(i)
    if (child.visibility != GONE) {
        measureChildWithMargins(child, widthSpec, 0, heightSpec, usedHeight)
    }
}
Q16

GONE、INVISIBLE、VISIBLE 对测量布局有什么影响？

★★★

INVISIBLE 通常仍参与测量布局但不绘制；GONE 通常不占空间，父容器测量时会跳过；VISIBLE 正常参与全部流程。

自定义 ViewGroup 要自行遵守 GONE 语义，系统不会替你的循环自动跳过。
05 · CANVAS DRAWING

Canvas、Paint 与文字

绘制题重点不在记 API，而在坐标系、状态栈、文字基线、硬件加速和每帧分配。

Q17

Canvas 的 save/restore 有什么作用？

★★★★★

保存和恢复变换矩阵、裁剪等绘制状态，避免 translate、rotate、scale、clip 影响后续绘制。

val checkpoint = canvas.save()
canvas.translate(centerX, centerY)
canvas.rotate(angle)
canvas.drawLine(0f, 0f, radius, 0f, paint)
canvas.restoreToCount(checkpoint)
Q18

Canvas.translate 会移动 View 吗？

★★★★★

不会，它只改变后续绘制坐标系，不改变 View 的 layout 边界、width/height 和触摸区域。移动 View 本身使用 translation 属性或重新布局。

Q19

文字为什么不能用 centerY 直接垂直居中？

★★★★★

drawText 的 y 是基线而不是文字中心。应使用 FontMetrics 的 ascent/descent 计算基线。

val fm = textPaint.fontMetrics
val baseline = centerY - (fm.ascent + fm.descent) / 2f
canvas.drawText(text, centerX, baseline, textPaint)
top/bottom 包含更宽松的字体边界；具体排版根据是否要统一行高选择指标。
Q20

ViewGroup 的 onDraw 为什么可能不执行？

★★★

ViewGroup 默认可能设置 willNotDraw，认为自己只负责子 View。需要绘制自身内容时调用 setWillNotDraw(false)，或通过背景触发相关绘制路径。

不要为了“保险”对所有 ViewGroup 都关闭 willNotDraw，会增加无意义绘制。
Q21

invalidate、postInvalidate 和 postInvalidateOnAnimation 区别？

★★★★★

invalidate 通常从 UI 线程请求重绘；postInvalidate 可跨线程投递；postInvalidateOnAnimation 与下一帧节奏同步，适合动画。

更好的状态模型仍是把 UI 更新切回主线程，而不是到处依赖 postInvalidate。
Q22

可以在 onDraw 中调用 invalidate 吗？

★★★

可以，但会形成持续重绘。动画应使用 ValueAnimator、Choreographer 或 postInvalidateOnAnimation，并在不可见或 detach 时停止。

无条件 invalidate 会导致 CPU/GPU 持续工作，即使画面几乎不变。
Q23

onDraw 中如何避免性能问题？

★★★★★

复用 Paint、Path、RectF，尺寸变化时预计算几何；避免每帧分配对象、解码 Bitmap、创建 Shader 和昂贵 saveLayer；只在状态变化时重绘。

private val arcPaint = Paint(Paint.ANTI_ALIAS_FLAG)
private val arcBounds = RectF()

override fun onDraw(canvas: Canvas) {
    super.onDraw(canvas)
    canvas.drawArc(arcBounds, -90f, sweepAngle, false, arcPaint)
}
Q24

硬件加速对自定义绘制有什么影响？

★★★

硬件加速把大量 Canvas 操作记录后交给 GPU，但不同版本对复杂 clip、阴影、Path 效果支持和代价不同。setLayerType 应针对真实问题，不是通用优化。

Q25

如何绘制清晰的 1px 线和处理密度？

★★★

业务尺寸用 dp/sp 转 px；像素对齐要考虑 stroke 居中覆盖两侧，奇数像素线有时需 0.5px 对齐。不要把所有尺寸写死为 px。

val density = resources.displayMetrics.density
val strokePx = 1f * density
paint.strokeWidth = strokePx
06 · TOUCH DISPATCH

事件分发与消费

先画出事件流，再讲 DOWN 的归属和中途拦截。只背 dispatchTouchEvent、onInterceptTouchEvent、onTouchEvent 三个名字不够。

Q26

触摸事件的分发顺序是什么？

★★★★★

事件从 Activity/Window 进入 View 树，ViewGroup.dispatchTouchEvent 决定是否询问 onInterceptTouchEvent，再向子 View 分发；最终由某个 onTouchEvent 消费。

Activity.dispatch→ViewGroup.dispatch→onIntercept→child.dispatch→onTouchEvent
dispatch 负责调度，intercept 只属于 ViewGroup，onTouchEvent 负责消费。
Q27

为什么 ACTION_DOWN 特别重要？

★★★★★

DOWN 决定当前手势序列的初始目标。View 如果不消费 DOWN，通常不会继续成为后续 MOVE/UP 的目标。

override fun onTouchEvent(e: MotionEvent): Boolean = when (e.actionMasked) {
    MotionEvent.ACTION_DOWN -> {
        downX = e.x
        isPressed = true
        true
    }
    MotionEvent.ACTION_MOVE -> { updateDrag(e.x); true }
    MotionEvent.ACTION_UP -> { performClick(); true }
    MotionEvent.ACTION_CANCEL -> { resetTouch(); true }
    else -> super.onTouchEvent(e)
}
Q28

父 View 中途拦截后子 View 会收到什么？

★★★★★

原目标子 View 收到 ACTION_CANCEL，后续事件转给父 View。子 View 必须在 CANCEL 中清理按压、拖动、VelocityTracker 和临时状态。

把 CANCEL 当成 UP 处理也可能错误：取消不代表用户完成了点击或拖拽提交。
Q29

OnTouchListener 与 onTouchEvent 谁先执行？

★★★★★

dispatchTouchEvent 通常先调用已启用 View 的 OnTouchListener；监听器返回 true 后，onTouchEvent 不再收到该事件。

dispatchTouchEvent→OnTouchListener→onTouchEvent
Q30

为什么自定义点击要调用 performClick？

★★★★★

它统一触发 OnClickListener 和无障碍点击语义，也支持键盘/辅助设备，并消除相关 Lint 警告。

override fun performClick(): Boolean {
    super.performClick()
    return true
}
Q31

pointerId 与 pointerIndex 有何区别？

★★★

pointerId 在当前事件序列中稳定标识一根手指；pointerIndex 只是当前 MotionEvent 数组位置，会随手指抬起重排。保存 id，用 findPointerIndex 动态查 index。

val index = event.findPointerIndex(activePointerId)
if (index != -1) {
    val x = event.getX(index)
    val y = event.getY(index)
}
07 · GESTURES

手势识别与滑动冲突

横竖嵌套、图片缩放、父容器抢事件是最常见的场景题。答案应包含方向判断、边界判断和 CANCEL 清理。

Q32

如何解决父子 View 滑动冲突？

★★★★★

外部拦截法由父 View 在 onInterceptTouchEvent 判断方向和边界；内部拦截法由子 View 通过 requestDisallowInterceptTouchEvent 控制父容器何时可拦截。

方向冲突比较 abs(dx) 与 abs(dy)，超过 touchSlop 后决定横向或纵向。
同向冲突先判断子 View 是否还能继续滚动，到了边界再交给父容器。
Q33

如何区分点击和滑动？

★★★★★

使用 ViewConfiguration.scaledTouchSlop 作为移动阈值，同时可结合按下时长和速度。不要写死像素值。

private val touchSlop = ViewConfiguration.get(context).scaledTouchSlop

val dragging = hypot(event.x - downX, event.y - downY) > touchSlop
Q34

GestureDetector、ScaleGestureDetector 和 VelocityTracker 分别做什么？

★★★

GestureDetector 识别点击、长按、滚动、fling；ScaleGestureDetector 识别双指缩放；VelocityTracker 计算指针速度，常与 OverScroller 配合惯性滚动。

VelocityTracker 使用后要 clear/recycle；多指时按 pointerId 获取速度。
Q35

requestDisallowInterceptTouchEvent 是否绝对禁止父 View 拦截？

★★★★★

它向祖先请求不要拦截当前手势，常规 ViewGroup 会遵守；但 DOWN 仍会经过父容器，而且父容器实现或窗口级机制仍可能影响事件。

回答时强调它是父子协作协议，不是修改事件目标的万能开关。
08 · SCROLL & ANIMATION

滑动、惯性与动画

区分“内容滚动”“View 位移”和“绘制坐标变化”，就不会把 scrollTo、translationX、Canvas.translate 混在一起。

Q36

scrollTo/scrollBy 移动的是什么？

★★★★★

移动的是 View 内容相对视口的位置，不改变 View 在父容器中的 layout 边界。移动 View 本身通常用 translationX/Y 或重新布局。

scrollTo设置绝对 scrollX/scrollY。
scrollBy在当前滚动值上增加偏移。
Q37

Scroller 会自己移动 View 吗？

★★★★★

不会，它只按时间计算当前位置。View 在 computeScroll 中读取 currX/currY、调用 scrollTo，并请求下一帧。

fun smoothTo(targetX: Int) {
    scroller.startScroll(scrollX, scrollY, targetX - scrollX, 0, 300)
    postInvalidateOnAnimation()
}

override fun computeScroll() {
    if (scroller.computeScrollOffset()) {
        scrollTo(scroller.currX, scroller.currY)
        postInvalidateOnAnimation()
    }
}
需要 fling 和越界回弹时通常使用 OverScroller。
Q38

补间动画和属性动画有什么区别？

★★★★★

传统 View Animation 主要改变渲染效果，旧模型下真实布局和点击区域可能不变；Property Animation 修改 translation、alpha、rotation 等真实属性，更适合交互。

translation 仍不改变 layout 左右边界，但 View 的变换和命中测试会纳入相关属性；不要简单等同“重新布局”。
09 · CUSTOM VIEWGROUP

自定义 ViewGroup

ViewGroup 题主要考两件事：怎样给子 View 生成约束，怎样在 onLayout 中把测量结果摆到正确位置。

Q39

自定义 ViewGroup 如何支持 MarginLayoutParams？

★★★★★

生成和检查 MarginLayoutParams，测量时使用 measureChildWithMargins，计算自身尺寸和子位置时把 margin、padding 都计入。

override fun generateDefaultLayoutParams() =
    MarginLayoutParams(LayoutParams.WRAP_CONTENT, LayoutParams.WRAP_CONTENT)

override fun generateLayoutParams(attrs: AttributeSet) =
    MarginLayoutParams(context, attrs)

override fun checkLayoutParams(p: LayoutParams) = p is MarginLayoutParams
Q40

流式布局的 onMeasure/onLayout 怎么设计？

★★★★★

测量阶段逐个测量可见子 View，累加当前行宽，超出可用宽度则换行，记录总高度；布局阶段用同样换行规则调用 child.layout。

if (lineWidth + childWidth > availableWidth && lineWidth > 0) {
    totalHeight += lineHeight
    maxLineWidth = maxOf(maxLineWidth, lineWidth)
    lineWidth = 0
    lineHeight = 0
}
lineWidth += childWidth
lineHeight = maxOf(lineHeight, childHeight)
两阶段的换行条件必须一致，还要处理 GONE、padding、margin、AT_MOST 和最后一行。
10 · QUALITY

状态保存与无障碍

能画出来只是及格。旋转恢复、TalkBack、键盘点击和生命周期清理，决定它是不是合格的生产组件。

Q41

自定义 View 如何保存和恢复状态？

★★★

继承 BaseSavedState/AbsSavedState 保存业务状态，onSaveInstanceState 包装 superState，onRestoreInstanceState 恢复后再交还父状态；View 还需要稳定 id。

override fun onSaveInstanceState(): Parcelable =
    SavedState(super.onSaveInstanceState()).also { it.progress = progress }

override fun onRestoreInstanceState(state: Parcelable?) {
    if (state !is SavedState) return super.onRestoreInstanceState(state)
    super.onRestoreInstanceState(state.superState)
    progress = state.progress
}
Q42

自定义 View 如何支持无障碍？

★★★★★

提供 contentDescription 或语义节点，正确实现 performClick，暴露可点击/可滚动状态；复杂虚拟子元素可使用 ExploreByTouchHelper。

最低要求TalkBack 能读出控件用途、当前值和可执行动作。
复杂图表不要只画像素；为数据点提供虚拟可访问节点或等价文本。
11 · DESIGN EXERCISES

六道实战设计题

面试现场先拆需求，再讲测量、状态、绘制、触摸、性能和无障碍。下面给的是答题骨架，不是唯一实现。

P01

圆形进度条

正方形测量；padding 内取最短边；RectF 缩进半个 stroke；drawArc 从 -90° 开始；ValueAnimator 更新 progress；提供文本和无障碍范围信息。

P02

流式标签布局

测量子 View + margin；按可用宽度换行；记录每行高度；布局复用相同规则；支持 RTL、GONE 和 AT_MOST。

P03

手写签名板

12 · TROUBLESHOOTING

常见故障快速定位

面试官经常把知识点包装成“为什么我的 View 不显示/不响应”。从尺寸、绘制、事件和状态四层排查。

现象优先检查典型原因
View 完全不显示measuredWidth/Height、可见性、父约束wrap_content 得到 0、GONE、没设置期望尺寸
onDraw 不执行是否为 ViewGroup、willNotDraw、尺寸ViewGroup 跳过自身绘制、宽高为 0
属性变化画面不更新setter 是否 invalidate/requestLayout只改字段没有触发刷新
点击收不到 UPDOWN 返回值、父容器拦截、CANCEL没消费 DOWN 或中途被父容器拦截
拖动明显卡顿onDraw 分配、invalidate 频率、主线程每帧创建对象、解码图片、全屏过度绘制
文字看起来不居中baseline、FontMetrics、Paint 对齐把 drawText 的 y 当成中心
旋转屏幕后状态丢失View id、SavedState、superState没有保存自定义状态或恢复链断裂

13 · CHEAT SHEET

面试前十分钟速查

这十条必须脱稿说清楚。

  1. measure → layout → draw 各自决定什么。
  2. MeasureSpec 的 EXACTLY、AT_MOST、UNSPECIFIED。
  3. wrap_content 如何计算期望尺寸。
  4. invalidate 与 requestLayout 的区别。
  5. draw 与 onDraw 的区别。
  6. Canvas save/restore 和坐标变换。
  7. 文字 baseline 的计算。
  8. dispatch、intercept、onTouchEvent 的事件链。
  9. 父子滑动冲突的外部/内部拦截方案。
  10. onDraw 如何避免分配与无效重绘。
最后提醒：回答任何自定义 View 题，都主动补上 padding、wrap_content、CANCEL、生命周期清理和无障碍，通常能明显拉开差距。
