01 · STUDY MAP

先按四轮复习，不要硬背词典

关键字的价值在于它改变了声明、控制流、类型系统或编译结果。先掌握语言骨架，再补齐低频边角。

1

基础骨架

val/var、fun、class、object、if、when、循环和异常。

2

客户端高频

空安全、sealed/data、visibility、lateinit、suspend。

3

拉开差距

inline 家族、reified、型变、委托和操作符约定。

4

扫清边角

多平台、注解目标、特殊标识符、保留词和符号。

面试答题公式：先说一句话定义 → 再说编译或运行语义 → 给一个 Android 场景 → 最后补一个易错边界。文档中的每张高频卡片都按这个顺序组织。

频率不是语言等级

★★★★★ 表示 Android 面试高频，★★★ 表示常见进阶，★ 表示低频或平台特定。低频词仍全部纳入索引与搜索。

02 · DECLARATIONS

声明与文件结构

Kotlin 用更少的声明语法表达更多约束。面试时最容易混淆的是“引用只读”与“对象不可变”、顶层声明与 Java static 的映射。

val / var

★★★★★稳定

val 只能赋值一次；var 可重新赋值。val 约束的是引用，不保证对象内部不可变。

val items = mutableListOf("A")
items += "B"            // 合法：引用没变，对象变了
// items = mutableListOf() // 编译错误

var state = "idle"
state = "loading"       // 合法
Java 对照局部 val 近似 final 变量；Kotlin 属性还可能生成 getter、setter 与 backing field。
Android 场景ViewModel 对外常暴露 val uiState，内部持有可变实现，缩小可变性边界。
易错：val list = mutableListOf() 仍可修改；真正只读 API 是 List，它也不等于深度不可变。
面试一句话：val 是只读引用/只读属性，而不是 immutable object；默认优先 val，让状态变化显式化。

fun

★★★★★

声明函数。Kotlin 支持顶层函数、局部函数、扩展函数、默认参数、命名参数和表达式函数体。

fun User.displayName(prefix: String = "@") =
    prefix + name

val text = user.displayName(prefix = "#")
Java 对照顶层函数在 JVM 上编译进文件类的静态方法；扩展函数也是静态方法，不具备虚派发。
客户端价值扩展函数适合无状态适配；不要借它隐藏复杂副作用或伪装成员多态。
易错：扩展函数按接收者的编译期类型静态解析；同名成员函数永远优先于扩展函数。

class / interface

★★★★★

class 声明类；interface 声明契约并可提供默认实现。Kotlin 类和成员默认是 final。

interface Loadable { fun retry() }

class HomeViewModel(
    private val repo: Repository
) : ViewModel(), Loadable {
    override fun retry() = repo.refresh()
}
Java 对照没有 extends/implements，统一使用冒号；若需继承必须显式 open 或 abstract。
Android 场景接口用于依赖倒置和测试替身；UI state 更适合 sealed 层次而不是接口随意扩展。

package / import / as

★★★

package 指定文件包；import 导入声明；as 可为导入创建别名，也用于不安全类型转换。

package feature.home

import android.graphics.Color as AndroidColor
import androidx.compose.ui.graphics.Color

val platform = AndroidColor.RED
Kotlin 包名不要求与目录完全一致，但 Android 项目应遵守目录约定。as 的两种角色要根据上下文区分。

typealias

★★★

为现有类型创建编译期别名，不产生新类型，也不提供额外类型安全。

typealias OnResult = (Result<User>) -> Unit
typealias UserId = String

// UserId 仍然就是 String，不能阻止参数传错
Java 对照Java 无直接语言级别名，通常用接口或包装类模拟。
选型只为缩短复杂类型用 typealias；要建立领域边界用 value class。

true / false

★★★★★

Boolean 字面量。Kotlin 条件必须是 Boolean，不存在 JavaScript/C 风格 truthy/falsy。

val hasData = items.isNotEmpty()
if (hasData) render(items)
// if (items.size) {} // 编译错误
03 · CONTROL FLOW

表达式与控制流

Kotlin 的 if、when、try 都能产生值。把“语句思维”转换成“表达式思维”，代码会更短也更容易保持状态一致。

if / else

★★★★★

if 是表达式，可直接返回分支结果；作为值使用时必须覆盖 else。

val title = if (user.isVip) "VIP" else "普通用户"

// Kotlin 没有 condition ? a : b 三元运算符
Java 对照替代一部分三元表达式；分支最后一个表达式就是结果。
Compose条件组合 UI 很自然，但要保持可组合调用位置稳定并理解重组。

when

★★★★★

强大的分支表达式，可按值、类型、区间或任意条件匹配；结合 sealed/enum 可获得穷尽性检查。

val text = when (val state = uiState) {
    UiState.Loading -> "加载中"
    is UiState.Content -> "${state.items.size} 条"
    is UiState.Error -> state.message
}
Java 对照比 switch 更广；无 fall-through，不需要 break。
面试重点sealed 层次新增子类时，穷尽 when 能让遗漏在编译期暴露。
以 sealed/enum/Boolean 等已知有限集合为 subject 时通常可省略 else；过早写 else 可能吞掉将来的新增状态。

for

★★★★★

遍历任何提供 iterator() 约定的对象，不是 Java 的三段式 for。

for ((index, item) in items.withIndex()) {
    println("$index: ${item.id}")
}

for (i in 0 until items.size) { /* 右开区间 */ }
for (i in items.indices) { /* 更直观 */ }
0..items.size 包含末端，访问数组会越界；使用 indices、until 或 ..<。

while / do

★★★

while 先判断再执行；do…while 至少执行一次。它们是循环表达式但结果类型为 Unit。

while (queue.isNotEmpty()) consume(queue.removeFirst())

do {
    val page = loadNext()
} while (page.hasMore)

break / continue

★★★

break 结束最近循环，continue 跳到最近循环下一轮；标签可明确跳出哪一层。

outer@ for (row in rows) {
    for (cell in row) {
        if (cell.isBlocked) break@outer
        if (cell.isEmpty) continue
    }
}
标签是 name@，引用是 break@name。不要用标签制造难以追踪的跨层流程。

return

★★★★★

从最近的函数或匿名函数返回。lambda 中用标签限定局部返回；内联 lambda 可能允许非局部返回。

items.forEach item@ { item ->
    if (!item.visible) return@item
    render(item)
}

fun find(): User? {
    users.forEach { if (it.active) return it } // forEach inline
    return null
}
非局部 return 依赖 inline；传给 noinline/crossinline 参数或普通高阶函数时不可这样返回。

try / catch / finally / throw

★★★★★

try 是表达式；throw 的类型是 Nothing，因此可以出现在 Elvis 右侧。Kotlin 没有受检异常。

val token = cache.read()
    ?: throw IllegalStateException("token missing")

val value = try { api.load() }
catch (e: IOException) { fallback() }
finally { trace.end() }
Java 对照不强制 throws/catch；finally 不改变建议——资源优先用 use。
Android 场景协程取消异常通常必须继续抛出，别被宽泛 catch(Exception) 吞掉。

typeof

★ 保留

官方列为保留供未来使用的硬关键字，当前不能作为普通标识符，也没有可用语义。

不要把它与 JavaScript 的 typeof、Kotlin 的 is 或 ::class 混为一谈。
04 · TYPES & NULL SAFETY

类型、转换与空安全

Kotlin 把空安全放入类型系统。面试不只问语法，还会追问智能转换为什么有时失效，以及平台类型如何破坏静态保证。

is / !is

★★★★★

运行时类型检查；编译器在控制流证明安全时自动 smart cast。

fun render(state: UiState) {
    if (state is UiState.Content) {
        println(state.items) // 已智能转换
    }
}
可变属性、开放 getter、跨线程可能变化的值或被闭包修改的变量，编译器无法证明稳定时不会 smart cast；先保存到局部 val。

as / as?

★★★★★

as 不安全转换，失败抛 ClassCastException；as? 安全转换，失败返回 null。

val activity = context as? ComponentActivity
    ?: return

val forced = context as ComponentActivity // 可能崩溃
Java 对照as? 把 instanceof + cast + null 合并。
建议优先设计正确类型边界；大量 as? 往往说明抽象或生命周期边界不清。

in / !in

★★★★★

可表示遍历、成员关系、when 条件，也能把泛型类型参数声明为逆变。

if (page in 1..lastPage) load(page)
if (id !in selectedIds) return

interface Consumer<in T> { fun accept(value: T) }
记忆：值层面的 x in y 会映射到 y.contains(x)；类型层面的 in T 表示“只消费 T”。

null

★★★★★

空引用常量。只有可空类型 T? 能持有 null；通过安全调用、Elvis、显式分支或契约缩小空值范围。

val title: String? = intent.getStringExtra("title")
val length = title?.length ?: 0

title?.let { toolbar.title = it }
!! 只是把潜在错误延迟到运行时；平台类型 T! 来自 Java，编译器无法替你保证是否为空。

this

★★★★★

引用当前接收者，也可从次构造器调用同类构造器；多接收者 DSL 中可用限定标签。

class Screen(val title: String) {
    fun bind(title: String) {
        this.title // 类属性（这里只读，不能赋值）
    }
}

with(receiver) { this@with.render() }
Compose/DSL 嵌套多个 receiver 时，隐式 this 可能读错作用域；必要时使用显式标签或更小的 DSL 块。

super

★★★

访问父类实现或调用父构造器；多个接口默认实现冲突时用尖括号限定。

override fun close() {
    super<Cacheable>.close()
    super<Traceable>.close()
}
05 · OBJECT-ORIENTED

面向对象与受限层次

Kotlin 默认关闭继承，鼓励组合和显式扩展。Android 面试常把 object、companion、data、sealed、value 与 Java 实现方式放在一起追问。

object / companion

★★★★★

object 同时声明类与单例实例，也能创建匿名对象；companion object 是类关联的伴生对象，不是 Java static。

object SessionRegistry { var current: User? = null }

class User private constructor(val id: String) {
    companion object {
        fun from(id: String) = User(id)
    }
}

val callback = object : Callback { override fun done() {} }
JVM 语义object 通常生成持有 INSTANCE 的类；companion 本身也是对象。Java 友好调用可选 @JvmStatic。
Android 风险进程级单例生命周期很长，不要持有 Activity/View；并发可变状态要显式同步。
追问：object expression 每次执行可创建新对象；object declaration 是惰性线程安全初始化的单例声明。

open / final / abstract / override

★★★★★

类和成员默认 final；open 允许继承/重写，abstract 强制子类实现，override 明确重写关系。

abstract class Store {
    abstract suspend fun load(): Data
    open fun clear() {}
}

class DiskStore : Store() {
    override suspend fun load(): Data = loadFromDisk()
    final override fun clear() {}
}
Java 对照Java 类默认可继承；Kotlin 采用“默认封闭”，降低脆弱基类问题。
测试提示不要为了 mock 把所有类 open；优先接口、依赖注入或测试友好的边界。

data

★★★★★

让编译器基于主构造器属性生成 equals/hashCode/toString/componentN/copy；适合值语义的数据载体。

data class ArticleUi(
    val id: Long,
    val title: String,
    val tags: MutableList<String>
)

val renamed = article.copy(title = "新标题")
copy() 是浅拷贝；上例的 tags 仍共享同一个 MutableList。data 不自动带来深度不可变。
Android常用于 UI state、网络 DTO 和列表 item；稳定性仍取决于属性类型。
继承边界data class 不能是 abstract/open/sealed/inner，但可以实现接口或继承其他类。

sealed

★★★★★

建立受限继承层次，使编译器知道直接子类型集合，是表达 UI 状态和领域结果的核心工具。

sealed interface UiState {
    data object Loading : UiState
    data class Content(val items: List<Item>) : UiState
    data class Error(val cause: Throwable) : UiState
}
与 enumenum 是固定实例集合；sealed 是受限类型集合，每个子类型可携带不同结构。
模块边界直接子类的位置受包和 source set 规则限制；多平台层次需关注 expect/actual。
面试重点：sealed + exhaustive when 把“新增状态后漏处理”从运行时 bug 变成编译期提醒。

enum

★★★

声明固定的枚举实例集合；枚举项可以有状态、实现接口和提供匿名类体。

enum class SortMode(val wire: String) {
    LATEST("latest"), POPULAR("popular");
}

val mode = enumValueOf<SortMode>("LATEST")
持久化或网络协议不要直接依赖 ordinal，枚举顺序变化会破坏兼容；显式保存稳定 wire value。

value

★★★

value class 创建轻量领域类型；在满足条件时 JVM 可避免包装，但装箱与名称改编仍会在部分边界出现。

@JvmInline
value class UserId(val raw: String)

fun load(id: UserId) {}
// load("42") // 编译错误：获得了 typealias 没有的安全性
适用ID、金额、规格化字符串等单值领域概念。
边界泛型、接口、可空和反射场景可能装箱；不要承诺“永不分配”。

annotation

★★★

annotation class 声明注解；目标、保留期、可重复性等由元注解约束。

@Target(AnnotationTarget.CLASS)
@Retention(AnnotationRetention.RUNTIME)
annotation class Screen(val route: String)
Android 常见框架会读取字段、getter 或参数上的注解；需要用 @field:、@get:、@param: 精确指定落点。

inner

★★★

嵌套类默认不持有外部类实例；加 inner 后才拥有外部引用并可访问其成员。

class Adapter {
    class Holder       // 类似 Java static nested class
    inner class Listener { fun adapter() = this@Adapter }
}
inner/匿名内部对象若被长生命周期组件持有，可能间接泄漏 Activity、Fragment 或 View。
06 · INIT & VISIBILITY

构造、初始化与可见性

初始化顺序和模块边界经常藏着 Android 生命周期问题。把“什么时候可用、谁能访问”讲清楚，比背修饰符更重要。

constructor / init

★★★★★

constructor 显式声明主/次构造器；init 是实例初始化块。主构造器参数、属性初始化器与 init 按源码顺序执行。

class Cache private constructor(
    private val dir: File
) {
    private val index = readIndex(dir) // 先执行
    init { require(dir.exists()) }      // 后执行

    constructor(path: String) : this(File(path))
}
次构造器必须直接或间接委托主构造器；不要在构造期间调用可重写成员，子类状态可能尚未初始化。

public / internal / protected / private

★★★★★

public 默认全局可见；internal 在同一编译模块可见；protected 仅类及子类；private 限当前类或顶层文件。

修饰符顶层类成员
public任意位置任意位置
internal同模块同模块
protected不可用当前类与子类
private同文件当前类
Java 差异Kotlin 没有 package-private；protected 不自动向同包开放。
Android 模块internal 的“模块”通常是一次 Gradle/Kotlin 编译单元，不等于 package。

lateinit

★★★★★

延后初始化非空 var；只能用于满足条件的属性/局部变量，读取前未赋值会抛 UninitializedPropertyAccessException。

private lateinit var binding: FragmentHomeBinding

override fun onCreateView(...): View {
    binding = FragmentHomeBinding.inflate(inflater)
    return binding.root
}

if (::binding.isInitialized) { /* 只在可访问作用域检查 */ }
lateinit 不管理生命周期。Fragment ViewBinding 更安全的做法是可空 backing property，并在 onDestroyView 清空。
lateinit vs lazy：lateinit 是可重新赋值的 var、外部负责初始化；lazy 是只读 val、首次访问计算并缓存。

const

★★★★★

const val 是编译期常量，只能放在顶层、object 或 companion，类型限 String 与基本类型，且初始化表达式必须可在编译期求值。

const val EXTRA_USER_ID = "extra_user_id"

object ApiConfig {
    const val TIMEOUT_MS = 5_000L
}
与 val普通 val 可在运行时初始化；const 会被当作编译期常量使用。
ABI 风险跨模块内联常量值变化后，使用方通常需要重新编译才能拿到新值。
07 · FUNCTIONS & GENERICS

内联、函数约定与泛型

这是中高级 Kotlin 面试的分水岭：需要同时理解源码语义、调用点展开、非局部返回和 JVM 类型擦除。

inline / noinline / crossinline

★★★★★

inline 允许编译器把函数体及可内联 lambda 展开到调用点；noinline 保留某个 lambda 对象；crossinline 禁止该 lambda 非局部返回。

inline fun runTask(
    crossinline action: () -> Unit,
    noinline onError: (Throwable) -> Unit
) {
    executor.execute { action() } // 换了执行上下文，不能 return 外层
    errorHandler = onError        // 被存储，不能内联
}
收益减少高阶函数的调用和 lambda 分配，并启用 reified/非局部返回。
代价代码体积、调试栈和 ABI 变化；不是普通小函数的无脑性能开关。
区分：noinline = 不展开且可存储/传递；crossinline = 仍可展开，但不许 return 跳出调用者。

reified

★★★★★

仅用于 inline 函数的类型参数，使调用点具体类型可用于 is、as、T::class 等操作。

inline fun <reified T : ViewModel>
    Fragment.vm(): T = ViewModelProvider(this)[T::class.java]
原理调用点展开后具体 T 被写入生成代码，绕开一般泛型的类型擦除限制。
Java 对照Java 通常显式传 Class<T>；reified 把这个 token 隐含在调用点。

out / in / where

★★★★★

out T 声明协变“只生产”，in T 声明逆变“只消费”；where 给类型参数添加多个上界。

interface Producer<out T> { fun next(): T }
interface Consumer<in T> { fun accept(value: T) }

fun <T> persist(value: T) where T : Entity, T : Parcelable {}
Java 对照声明处型变对应一类稳定的 ? extends / ? super 使用方式；Kotlin 也支持 use-site projection。
口诀PECS：Producer Extends ≈ out；Consumer Super ≈ in。
List<out T> 常是多余的，因为 Kotlin 的只读 List 已声明为 List<out E>。

operator / infix

★★★

operator 让约定名称函数参与运算符语法；infix 允许单参数成员/扩展函数省略点和括号调用。

data class Px(val value: Int) {
    operator fun plus(other: Px) = Px(value + other.value)
}

infix fun String.has(text: String) = contains(text)
val ok = "Kotlin" has "lin"
不能发明新运算符；可重载的符号映射到固定函数名。infix 优先级低于算术和区间、高于 &&/|| 等，复杂表达式加括号。

tailrec

★

标记尾递归函数；编译器在满足“递归调用是最终操作”等条件时将递归改写为循环。

tailrec fun gcd(a: Int, b: Int): Int =
    if (b == 0) a else gcd(b, a % b)
递归结果后还有加法、try/catch/finally 某些位置或 open 函数等情形不能优化；留意编译器警告。

vararg

★★★

允许参数接收可变数量的值；函数内部表现为数组，已有数组用展开运算符 * 传入。

fun tags(vararg values: String) = values.joinToString()
val base = arrayOf("android", "kotlin")
val text = tags(*base, "compose")
展开可能涉及数组复制；热点路径不要为了语法方便频繁拼接大型 vararg。
08 · COROUTINES

suspend：能暂停，不等于后台线程

Kotlin 语言只提供挂起函数机制，协程调度、Scope、Job、Dispatcher、Flow 来自 kotlinx.coroutines 等库。把语言和库分开回答是面试加分项。

suspend

★★★★★语言机制

标记挂起函数或挂起 lambda。它能在不阻塞线程的前提下挂起并稍后恢复，但不会自动切线程，也不自动保证异步。

class UserRepository(
    private val api: UserApi,
    private val io: CoroutineDispatcher
) {
    suspend fun load(id: String): User = withContext(io) {
        api.load(id)
    }
}

viewModelScope.launch {
    runCatching { repository.load(id) }
        .onSuccess { _state.value = UiState.Content(it) }
}
编译语义大体改写为带 Continuation 的状态机；挂起点保存局部状态，恢复后继续执行。
线程语义是否切换由调用的挂起函数/Dispatcher 决定；纯 CPU suspend 函数仍可能阻塞当前线程。
调用限制只能从另一个 suspend 函数或协程体等挂起上下文调用。
取消：协程取消是协作式的。会挂起的库函数通常检查取消；CPU 循环应检查 ensureActive()/yield()。不要吞掉 CancellationException。
标准回答：suspend 是编译器支持的“可挂起函数”标记，不创建线程、不等同异步；协程构建器启动协程，调度器决定执行线程，挂起函数决定何时释放线程等待。

三个连续追问

  1. suspend 会自动在 IO 线程执行吗？不会。
  2. 挂起时线程发生什么？当前协程保存续体并让出线程；线程可执行别的任务。
  3. suspend 能从 Java 直接自然调用吗？JVM 签名包含 Continuation，通常通过 Kotlin 包装 API 或协程桥接更合适。
09 · DELEGATION & DSL

委托、访问器与 DSL 接收者

属性语法是 Kotlin 客户端代码的重要组成部分。理解 getter/setter、backing field 和 delegate，才能看懂 lazy、observable、Compose state 与 ViewBinding 委托。

by

★★★★★

用于类委托和属性委托：前者把接口实现转发给对象，后者把 get/set 交给提供约定函数的 delegate。

class LoggingList<T>(
    private val target: MutableList<T>
) : MutableList<T> by target

val config by lazy { readConfig() }
var title by Delegates.observable("") { _, old, new ->
    log("$old -> $new")
}
编译语义属性委托会调用 getValue/setValue 约定；不是魔法字段访问。
Composevar x by remember { mutableStateOf(...) } 依赖 State 的委托操作符。
类委托只转发接口成员；若委托对象内部调用自己的成员，不会自动动态回调包装类的同名 override。

get / set / field

★★★★★field 有版本敏感用途

get/set 定义属性访问器；访问器里的特殊标识符 field 指向 backing field。官方 2.4.10 参考还列出 field 声明显式 backing field 的用途。

var username: String = ""
    get() = field.trim()
    private set(value) {
        field = value
    }

val fullName: String
    get() = "$firstName $lastName" // 无 backing field
在 getter 中写 return username 会递归调用 getter；需要存储时用 field。显式 backing field 是否可用应以项目编译器和语言设置为准。

注解使用点目标

★

file、field、property、get、set、receiver、param、setparam、delegate 指定注解落到生成结构的哪一处。

@file:JvmName("Formatters")

data class User(
    @field:Json(name = "user_id")
    @param:Named("id")
    val id: String
)

fun @receiver:Fancy String.decorate() = this
关键差异property 是 Kotlin 属性元数据，不一定能从 Java 看到；field/get/param 面向不同生成元素。
框架排错序列化或注入注解“不生效”时，先检查库读取的是字段、getter 还是构造参数。
10 · PLATFORM & RARE

多平台与平台特定低频词

Android 日常较少直接写，但读公共模块、JNI 或 Kotlin/JS 代码时会遇到。这里保持定义准确、篇幅克制。

expect / actual

★★★ KMP

expect 在公共 source set 描述平台能力，actual 在目标平台提供匹配实现。

// commonMain
expect fun platformName(): String

// androidMain
actual fun platformName(): String = "Android ${Build.VERSION.SDK_INT}"
它不是传统接口的万能替代；能用公共接口 + 平台依赖注入表达时通常更灵活。匹配规则与可见性要由编译器校验。

external

★

标记实现位于 Kotlin 之外，例如 JVM 的 JNI native 方法或 Kotlin/JS 外部声明。

external fun nativeDecode(bytes: ByteArray): Bitmap

companion object {
    init { System.loadLibrary("codec") }
}
编译器只接受声明；签名不匹配、库未加载、ABI/线程/内存错误仍在运行时暴露。

dynamic

★ Kotlin/JS

Kotlin/JS 的动态类型，绕开部分静态类型检查；Kotlin/JVM/Android 不能使用。

// Kotlin/JS only
fun read(obj: dynamic): String = obj.title as String

context（版本敏感语法词）

★ 另行关注

用于 context parameters/receivers 相关语法的上下文 token。它未出现在本页所核对的官方“Keywords and operators”稳定分类清单中，因此不计入顶部关键字数量。

这类特性随 Kotlin 语言版本和编译选项演进很快；面试或项目使用时必须以当前编译器文档为准，不要把旧的 context receivers 与新的 context parameters 混写。
11 · SPECIAL IDENTIFIERS & OPERATORS

特殊标识符、运算符与符号

官方关键字参考把这些内容放在同一页。符号不是“关键字”，但它们共同构成 Kotlin 语法表面，面试中空安全、相等性和操作符约定尤其高频。

it

★★★★★特殊标识符

单参数 lambda 省略显式参数名时，编译器提供的隐式名称；在其他上下文仍可作为普通标识符。

users.filter { it.active }

// 嵌套 lambda 时显式命名更清晰
users.map { user ->
    user.roles.any { role -> role.isAdmin }
}
多层 it 会迅速降低可读性；只要 lambda 稍复杂或嵌套，立即给参数起业务名。

_ / `反引号`

★★★

_ 忽略 lambda 或解构中不用的值；反引号把任意字符串变成标识符，常用于测试名和 Java 互操作中的冲突名称。

map.forEach { (key, _) -> println(key) }

@Test
fun `empty cache returns null`() {}

javaObject.`is`() // Java 方法名与 Kotlin 关键字冲突

!! / ?. / ?: / ?

★★★★★ 空安全

? 标记可空类型；?. 安全调用；?: Elvis 提供空值替代；!! 强制断言非空并可能抛 NPE。

val name: String? = user?.profile?.name
val display = name ?: "游客"
val forced = name!! // 仅当外部不变量确实可靠时考虑
Elvis 只判断 null，不判断空字符串、0 或 false。!! 不是“转为非空”的安全转换。

== / != / === / !==

★★★★★ 相等性

== 是结构相等，空安全地调用 equals；=== 是引用同一性。对应的不等操作符分别是 !=、!==。

val a = String(charArrayOf('K'))
val b = String(charArrayOf('K'))
println(a == b)   // true：内容相等
println(a === b)  // 通常 false：不是同一引用
Java 对照Kotlin 的 == 更接近 Java Objects.equals；=== 才接近引用类型的 Java ==。
注意浮点数相等在静态类型和泛型/Any 场景存在 IEEE 与 equals 语义差异，需单独查证。

+ − * / % ++ --

★★★★★

算术、递增递减运算符。对自定义类型映射为 plus/minus/times/div/rem/inc/dec 等约定函数。

val next = current + delta       // current.plus(delta)
counter++                        // 调用 inc 并重新赋值
fun send(vararg ids: Long) {}
send(*idArray)                   // * 还可展开 vararg
Kotlin 不做 Java 式隐式扩大/缩小数字转换，例如 Long 不能直接赋给 Int；整数除法仍会截断小数部分。

= / += / -= / *= / /= / %=

★★★★★

= 用于赋值和默认参数；增强赋值会优先按约定解析为 plusAssign 等，或退化为 a = a + b。

fun load(force: Boolean = false) {}

items += newItem // 具体行为取决于 items 类型与可用操作符
val list += item 可能是修改可变集合，也可能创建新集合再赋值而失败。看清静态类型和 plusAssign/plus 的解析。

&& / || / ! / < / > / <= / >=

★★★★★

&&/|| 短路求值，! 逻辑取反；比较操作对自定义类型映射为 compareTo。

if (user != null && user.active) render(user)
if (version >= minVersion) enable()
Kotlin 位运算不是符号 & | ^，而是 Int/Long 的 and/or/xor/inv/shl/shr/ushr 中缀函数。

[] / .. / ..< / . / ::

★★★★★

[] 映射 get/set；.. 创建闭区间，..< 创建右开区间；点号访问/限定成员；:: 创建函数、属性或类引用。

cache[key] = value        // set；读取映射 get
for (i in 0..lastIndex) {}
for (i in 0..<size) {}
val factory = ::User
val type = User::class

: / -> / @ / ; / $

★★★ 语法符号

冒号分隔名称与类型/父类型；箭头分隔 lambda、函数类型或 when 分支；@ 引入注解/标签/限定 this；分号分隔同一行语句；$ 用于字符串模板。

val mapper: (User) -> String = { user -> user.name }

loop@ for (item in items) {
    if (!item.valid) continue@loop
}

println("user=${user.id}")

对照不是逐字翻译。Kotlin 很多语法会生成 Java 可见结构，但语言语义、默认值和调用体验并不完全相同。

13 · INTERVIEW DRILLS

Android 客户端面试题库

先自己用 30–60 秒回答，再展开参考答案。答案刻意保留继续追问的入口。

1. val 声明的集合一定不可变吗？
不一定。val 只保证引用不能重新赋值；若实际对象是 MutableList，内容仍可修改。List 是只读接口，也不保证底层对象或元素深度不可变。
2. suspend 函数一定运行在后台线程吗？
不一定。suspend 只允许函数挂起/恢复；线程由当前协程上下文和具体挂起函数决定。CPU 密集任务需要显式选择合适 Dispatcher 或执行器。
3. inline、noinline、crossinline 的区别？
inline 允许函数及 lambda 在调用点展开；noinline 让指定 lambda 不展开，因此可保存/传递；crossinline 仍可展开，但禁止非局部 return，适合在另一个执行上下文调用。
4. data class 的 copy 是深拷贝吗？
不是，是浅拷贝。主构造器属性按引用复制；可变集合、对象图仍共享。深拷贝要显式复制内部结构或设计不可变模型。
5. sealed class 和 enum 怎么选？
固定同构实例集合用 enum；每种状态需要不同字段/行为时用 sealed 层次。两者配合 when 都可获得穷尽性检查。
6. lateinit 与 lazy 的差别？
lateinit 是稍后由外部赋值的非空 var，未初始化读取会抛异常；lazy 是 val 的委托，首次访问计算并缓存，并可配置线程安全模式。
7. object 和 companion object 等同 static 吗？
不等同。二者都会生成对象实例；companion 是与类关联的伴生对象。JVM 上可通过 @JvmStatic/@JvmField 暴露更像静态的 Java API。
8. smart cast 为什么有时失效？
编译器必须证明检查后值不会变化。可变属性、开放 getter、跨线程或闭包内可变变量可能失效。保存到稳定局部 val 往往能解决。
9. reified 如何绕过类型擦除？
它不改变 JVM 全局类型擦除；inline 把函数展开到调用点，编译器把具体类型操作写入生成代码，因此能用 T::class、is T 等。
10. internal 在 Android 中的边界是什么？
同一 Kotlin 编译模块，而不是 package。通常与 Gradle 模块/变体编译任务相关；测试 source set 可能拥有额外 friend-path 可见性。
11. 什么时候用 by 委托？
当一组转发或属性存取策略可以复用时。类委托减少接口样板，属性委托封装 lazy/observable/state 等策略；不要用它隐藏复杂生命周期。
12. == 与 === 有什么区别？
== 是结构相等并空安全调用 equals；=== 是引用同一性。Java 开发者最容易误把 Kotlin == 当作引用比较。
