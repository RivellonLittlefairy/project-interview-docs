Kotlin 常用数据结构：API、用法与优缺点

读完能回答三个问题：这批数据用什么装？常见增删查改怎么写？为什么选它，有什么代价？先看 P1，再按业务需要补 P2。

01 · 先选类型：你想怎么使用这批数据？

这篇面向 Android / Kotlin 开发者，讲解常用数据结构、API、执行结果和选型理由。以 Kotlin/JVM 为主要环境；Java 集合可直接从 Kotlin 使用。示例是独立片段，可分别放进 fun main() { ... } 中执行，彼此不共享变量。类名写全包名的地方，也可以改为文件顶部的 import。示例都是教学数据，不代表项目已经使用。

P1 先掌握：数组、List、Set、Map、只读与可变、常用操作和常见坑。P2 再看：栈与队列、优先队列、有序集合、Sequence 和 Android 专用容器。无需一遍背完全部 API。

需求优先考虑原因 / 代价
固定数量的整数、坐标、采样值IntArray / FloatArray长度固定，按下标读写；JVM 原生数值数组避免泛型元素装箱
展示列表、保持顺序、允许重复List；需要增删时 MutableList / ArrayList有位置语义；数组列表中间插入和删除需要搬移
记录已选 ID、去重、判断存在Set / MutableSet不保留重复元素；不能把位置当作业务含义
按 userId 查用户、按 key 存配置Map / MutableMapkey 唯一，value 可以重复；占用额外索引空间
先进先出的任务；后进先出的撤销记录ArrayDeque两端操作方便；普通双端队列不是线程安全任务通道
每次取优先级最高 / 数值最小的任务java.util.PriorityQueue只保证队头优先级；遍历不保证有序
始终按 key 或元素排序；找前驱后继java.util.TreeMap / TreeSet树结构维护有序性，基本操作通常 O(log n)
小规模、整数 key 的 Android 映射SparseArray / LongSparseArray节省 key 装箱及部分结构开销；不保证比 HashMap 更快

先分清两个维度：“列表 / 集合 / 映射”描述数据关系，“数组 / 哈希表 / 树 / 链表”描述实现方法。List、Set、Map 是接口层概念；ArrayList、HashSet、HashMap 才是具体实现。复杂度要落到实现和操作上。

02 · P1：val、只读集合、不可变集合不是一回事

写法 / 概念能做什么不保证什么
val items = mutableListOf(1)不能给 items 重新赋另一对象；可以 items.add(2)val 不会冻结对象
List<Int>通过这个引用只读，没有 add / remove 接口同一底层集合可能经由其他引用被修改
MutableList<Int>接口允许增删改不意味着线程安全，也不意味着元素不可变
source.toList()创建内容快照，后续 source 结构变化不影响结果浅拷贝；里面的可变对象仍然可能共用
不可变集合 / 持久化集合依其实现提供更强的结构不变约束；持久化集合更新可共享结构不是所有 listOf 返回值的统一承诺；也不会自动冻结元素对象
Kotlin · readonly-view
val source = mutableListOf("A")
val readOnly: List<String> = source
val snapshot = source.toList()
source.add("B")
println(readOnly) // 与 source 指向同一集合
println(snapshot) // 调用 toList 时的内容
// readOnly.add("C") // 编译不通过：只读接口没有 add
// source = mutableListOf("C") // 编译不通过：source 是 val

运行结果：

[A, B]
[A]

listOf / setOf / mapOf 返回只读接口，mutableListOf 等返回可变接口。不要用强制类型转换去“获得可变能力”：工厂函数在不同数量、平台或版本下可能采用不同实现，转换或写入可能失败。需要修改时明确调用 toMutableList()。

03 · P1：Array 和原生类型数组——固定长度的一排格子

数组创建后长度固定，但格子里的值可以替换。按下标访问类似直接打开某个编号的抽屉。Kotlin 的 Array<Int> 在 JVM 上保存装箱整数引用；IntArray 对应 int[]，没有每个元素的泛型装箱成本。ByteArray 常用于文件和网络字节，FloatArray 常用于图形或采样。

API用途注意
intArrayOf(1, 2) / IntArray(3) { it * 10 }直接列值 / 按下标初始化IntArray(3) 默认全 0；Array(3) { ... } 需初始化元素
arrayOf("A", "B") / arrayOfNulls<String>(3)引用类型数组 / 全 null 数组后者元素类型是 String?
a[i]、a[i] = v、size、indices读取、改值、长度、合法下标范围越界会抛异常
getOrNull(i) / getOrElse(i) { ... }安全读取 / 提供越界默认值避免用异常做普通分支
copyOf() / copyOf(newSize)复制 / 复制到新长度新数组；数值扩展部分补 0，引用数组扩展部分可出现 null，谨慎使用
contentEquals / contentDeepEquals内容比较 / 嵌套引用数组深层比较数组 == 不是逐元素比较
sort() / sorted()原地排序 / 返回新的排序 List需要排序数组副本时用 sortedArray()
toList() / asList()内容快照 / 数组支持的列表视图asList 会反映后续数组元素替换；别误当独立副本

优点：下标访问快，固定长度数据简单直接，原生数值数组紧凑。缺点：长度不能原地增长，插入 / 删除通常需要新数组或移动元素；a + value 会创建新数组，循环中反复追加会产生大量复制。业务数据条数变化明显时通常选可变列表。

04 · P1：List / ArrayList——有顺序、可重复的列表

List 表达“第几个元素”的语义，元素允许重复。常规动态业务列表通常用数组列表；mutableListOf 在 Kotlin/JVM 的常见实现是 ArrayList，但需要明确实现特性时直接写 ArrayList<T>()。容量 capacity 是预留空间，size 才是已有元素数量。

API含义返回值 / 细节
listOf / mutableListOf / arrayListOf只读接口 / 可变接口 / 明确 ArrayList空集合需类型，例如 mutableListOf<String>()

set(i, x) / [i] = x替换已有位置set 返回原元素；赋值语句不用其返回值

contains(x) / x in list / indexOf(x)包含检查 / 查首个位置未找到 indexOf 返回 -1；数组列表需要线性查找
firstOrNull() / lastOrNull() / find { ... }首尾 / 首个符合条件元素无结果返回 null；first() 在空集合上会抛异常
clear() / isEmpty() / size清空 / 判空 / 数量清空只解除集合持有的元素引用，不等于对象立即被回收

ArrayList 和 LinkedList 怎么取舍？

操作 / 特性ArrayListjava.util.LinkedList
底层思路可扩容数组双向链表，每个节点带链接
按下标访问O(1)O(n)，需要从某一端走到对应节点
尾部追加均摊 O(1)，扩容那次需要 O(n) 复制O(1)
中间按下标插入 / 删除O(n)，移动后面的元素定位仍是 O(n)；已经用迭代器定位后，节点链接调整 O(1)
内存与遍历局部性引用相邻存放，通常更紧凑节点对象额外开销，遍历需沿链接跳转
选用建议普通业务列表的常用起点已定位节点附近反复增删等明确需求；仅做栈队列通常先看 ArrayDeque

优点：顺序和重复值都保留，随机访问、遍历和尾部追加适合业务列表。缺点：按值查找和中间删除是线性成本。别把“链表增删 O(1)”理解成“按下标在任何位置增删都是 O(1)”。

05 · P1：Set——只关心有没有，不接受重复值

例如已选用户 ID、已曝光内容 ID、权限集合。Set 保证元素唯一，但不同实现的遍历顺序不同；去重不等于排序。某些扩展函数允许 elementAt(i)，也不意味着 Set 具备列表的下标访问性能和位置语义。

实现 / 工厂顺序优劣
HashSet / hashSetOf不承诺遍历顺序哈希分布合理时增删查平均 O(1)，额外哈希空间
LinkedHashSet / linkedSetOf插入顺序去重且保持首次加入顺序，需要额外维护顺序
TreeSet / sortedSetOf自然顺序或比较器顺序增删查 O(log n)，支持范围操作；唯一性由比较结果决定
setOf / mutableSetOf按工厂文档保留元素迭代顺序只读 / 可变接口，不要把它们等同于 hashSetOf 的无序约定
Kotlin · set-operations
val selected = linkedSetOf("B", "A", "B")
println(selected)
println(selected.add("A")) // 已存在
println(selected.add("C"))
println("B" in selected)
println(selected.remove("B"))
val other = setOf("C", "D")
println(selected union other)
println(selected intersect other)
println(selected subtract other) // 不修改 selected
println(selected)

运行结果：

false
true
true

add 返回是否真的新增，remove 返回是否真的删除；contains 和 in 用于判存在。union（并集）、intersect（交集）、subtract（差集）返回结果集合。list.distinct() 返回保留首次出现顺序的去重 List，distinctBy { it.id } 按指定字段去重并保留首个元素。

优点：表达唯一性，哈希集合适合频繁判存在。缺点：会丢掉重复次数，不适合按位置取值；元素参与 equals / hashCode 的字段不应在入集合后改变，详见常见坑。

06 · P1：Map——通过唯一 key 找 value

例如 userId → User，不用每次遍历整份用户列表。key 唯一，重复写同一个 key 会覆盖 value；不同 key 的 value 可以相同。"id" to 1 创建一个 Pair，经常用来初始化 Map。Map 不继承 Collection，但 keys / values / entries 能供遍历。

API用途注意
mapOf / mutableMapOf构建只读 / 可变映射重复 key 保留后写入的 value；工厂保留条目迭代顺序
map[key] / get(key)获取 value不存在返回 null；允许可空 value 时可能与存储 null 混淆
map[key] = value / put(key, value)写入或覆盖put 返回旧值或 null
containsKey(key) / key in map判断 key 存不存在containsValue(value) 通常需要遍历，不是哈希 key 查找
getValue(key)读取必须存在的 key普通 Map 缺失时抛异常；withDefault 包装可提供隐式默认值
getOrDefault(k, d) / getOrElse(k) { d }读不到时的默认值前者在 key 缺失时给默认；后者对缺失或 null 给默认；均不写回
getOrPut(k) { value }没有非 null 值时计算并写回存储 null 也会调用默认函数；普通 MutableMap 不是原子操作
remove(k) / putAll(other) / clear()删除 / 批量覆盖 / 清空remove 返回被删值或 null
keys / values / entries遍历 key / value / 键值对这些视图会反映原 Map 后续变化，需要快照时复制

实现顺序适合 / 代价
HashMap / hashMapOf不承诺遍历顺序哈希分布合理时按 key 增删查平均 O(1)；有哈希结构开销
LinkedHashMap / linkedMapOf通常为插入顺序需要稳定遍历；JVM 构造器可显式启用访问顺序，为 LRU 提供基础但不会自动限制容量
TreeMap / sortedMapOf按 key 排序O(log n) 基本操作，适合范围查询；需要可比较的 key 或 Comparator

优点：按 ID 查询直接，关系表达清楚。缺点：比纯列表多一层索引开销；重复 key 会覆盖，可能丢掉数据；哈希映射不是按 value 搜索的索引。

07 · P2：用 ArrayDeque 实现栈和队列

栈 Stack：后放进去的先取出（LIFO），例如撤销记录。队列 Queue：先放进去的先取出（FIFO），例如待处理任务。双端队列 Deque：两头都能进出，因此两种行为都能实现。

行为Kotlin ArrayDeque API示例含义
队列：尾部入、头部出addLast(x) + removeFirstOrNull()A、B 依次加入，取出顺序 A、B
栈：尾部入、尾部出addLast(x) + removeLastOrNull()A、B 依次加入，取出顺序 B、A
查看两端，不删除firstOrNull() / lastOrNull()空集合返回 null
必须有元素才删除removeFirst() / removeLast()空集合抛异常
从另一端插入addFirst(x)放到队头，不必移动全部元素
Kotlin · deque
val queue = kotlin.collections.ArrayDeque<String>()
queue.addLast("A")
queue.addLast("B")
println(queue.removeFirstOrNull())
println(queue.removeFirstOrNull())
println(queue.removeFirstOrNull())

val stack = kotlin.collections.ArrayDeque<String>()
stack.addLast("A")
stack.addLast("B")
println(stack.removeLastOrNull())
println(stack.removeLastOrNull())

运行结果：

A
B
null
B
A

优点：基于可扩容环形数组，两端增删通常是均摊 O(1)，比用 ArrayList.removeAt(0) 搬移元素更适合队列。缺点：查找某个值或删除中间元素仍可能 O(n)，扩容会有复制成本，也不自带线程安全或背压。不要用普通队列代替协程 Channel 的通信语义。

两个 ArrayDeque 别混用：kotlin.collections.ArrayDeque 自 Kotlin 1.4 起提供，可存 nullable 元素；java.util.ArrayDeque 是 JVM/Android 的 Java 容器，不允许 null，空队列安全取出用 pollFirst() / pollLast()，安全查看用 peekFirst()。Android 上 Java ArrayDeque 自 API 9 可用。如果 Kotlin 队列允许 null，取出 null 就不能单独区分“队列空了”和“取到 null”。

08 · P2：PriorityQueue 和 TreeMap / TreeSet

PriorityQueue：每次弹出当前最优先的元素

默认自然顺序把最小值放在队头；自定义比较器可以让高优先级任务先执行。其底层通常是堆，不是整体排好序的列表。offer 入队，peek 查看队头，poll 取出队头；peek / poll 在空队列返回 null，不能放 null 元素。

Kotlin · priority-queue
data class Job(val name: String, val priority: Int)
val queue = java.util.PriorityQueue<Job>(
    compareByDescending<Job> { it.priority }.thenBy { it.name }
)
queue.offer(Job("download", 1))
queue.offer(Job("payment", 5))
queue.offer(Job("upload", 3))
println(queue.peek()?.name)
while (queue.isNotEmpty()) {
    println(queue.poll().name)
}

运行结果：

payment
payment
upload
download

优点：入队 / 出队 O(log n)，看队头 O(1)，无需每次对所有任务排序。缺点：遍历和 toList() 不保证排序；查某个值 / 删除指定对象通常 O(n)。相同优先级不承诺 FIFO，业务需要稳定顺序就加入递增序号作为第二排序字段。不要直接修改队中对象的优先级；堆不会自动重排，应移除后修改再加入。

TreeMap / TreeSet：始终按比较规则维护顺序

Kotlin · tree-map
val levels = java.util.TreeMap<Int, String>()
levels[10] = "beginner"
levels[30] = "advanced"
levels[20] = "intermediate"
println(levels.keys)
println(levels.floorKey(25))   // 最大的 <= 25 的 key
println(levels.ceilingKey(25)) // 最小的 >= 25 的 key
println(levels.subMap(10, true, 30, false).keys)

运行结果：

[10, 20, 30]
20
30
[10, 20]

firstKey / lastKey 取边界；lowerKey / higherKey 取严格小于 / 大于；floorKey / ceilingKey 可以等于。TreeMap 的范围结果是关联视图，独立保存时再复制。Android 的这些 NavigableMap 范围与邻近查询 API 需 API 9+。

优点：不用每次排序，可以做有序遍历和范围查找。缺点：单次查找通常比理想哈希查找成本高，有树节点开销。TreeSet 把比较器返回 0 的两个元素视作同一位置，即使它们的 equals 不同；自定义排序字段时必须同时考虑“谁算重复”。

09 · P1：集合常用操作——筛选、变换、分组、排序

下面这些通常是 Kotlin 扩展函数，很多可用于多种集合。先问“返回什么”和“原集合变不变”，比死记方法名更容易。

10 · P2：Sequence——控制处理过程，不是新的存储容器

普通集合的 filter().map().take() 通常分阶段立即执行，各阶段可能建立中间列表。Sequence 将处理延迟到终止操作，按需把元素逐个通过处理链，可以减少中间集合和不必要的遍历。它不是协程 Flow，也不会自动切线程或并行。

Kotlin · sequence
val numbers = listOf(1, 2, 3, 4, 5, 6)
val result = numbers.asSequence()
    .filter {
        println("check $it")
        it % 2 == 0
    }
    .map {
        println("map $it")
        it * 10
    }
    .take(2)
println("before toList")
println(result.toList())

运行结果：

before toList
check 1
check 2
map 2
check 3
check 4
map 4
[20, 40]

上面直到 toList() 才开始处理，找到两个结果后就不再检查 5、6。适合：多步转换、数据量较大、只需要前几个结果。代价：迭代器及函数调用开销，小集合不一定更快；sorted() 这类操作仍需先收集数据才能产出排序结果；Sequence 不是缓存，重复消费可能重新计算，有些序列甚至只允许消费一次。

11 · P1：复杂度与选型速查

n 是元素个数。O(1) 表示操作次数不随 n 线性增长，不是“耗时 1 毫秒”；O(log n) 增长较慢；O(n) 通常要扫描或移动一批元素。均摊指一串操作合起来分摊成本，例如数组列表偶尔扩容但多数追加很便宜；平均则依赖数据和哈希分布等假设。

具体实现读取 / 查找插入删除顺序与注意
Array / IntArray下标 O(1)，按值 O(n)无原地扩长；构造新数组 O(n)通常要移动或构造新数组 O(n)固定长度，按下标顺序
ArrayList下标 O(1)，按值 O(n)末尾均摊 O(1)；中间 O(n)末尾 O(1)；中间或按值 O(n)顺序可重复，扩容一次 O(n)
LinkedList下标 / 按值 O(n)两端 O(1)；按下标含定位 O(n)两端 O(1)；按下标含定位 O(n)已定位迭代器处修改可 O(1)
HashSet / HashMap按元素 / key 平均 O(1)平均 O(1)平均 O(1)哈希冲突或扩容可能更贵，不承诺遍历顺序
LinkedHashSet / LinkedHashMap按元素 / key 平均 O(1)平均 O(1)平均 O(1)维护顺序，增加内存开销
TreeSet / TreeMapO(log n)O(log n)O(log n)比较顺序；复杂度另受比较器自身成本影响
ArrayDeque两端查看 O(1)，按值查找 O(n)两端均摊 O(1)两端通常 O(1)，按值删除 O(n)适合栈队列；Kotlin 版本还支持按下标 O(1)
PriorityQueue队头 O(1)，按值 O(n)O(log n)队头 O(log n)，指定对象 O(n)只保证队头优先，不保证遍历顺序

哈希容器的平均 O(1) 假设 hashCode / equals 本身开销合理且分布良好；不能说任意输入的最坏情况都是 O(1)。具体 JVM/Android 实现对严重冲突的处理可能不同。业务里几条数据常常更应优先可读性；热路径上的大集合才值得测量并优化。

Kotlin · membership
val selectedIds = listOf(2, 4, 6).toHashSet()
val allIds = listOf(1, 2, 3, 4, 5)
println(allIds.filter { it in selectedIds })

运行结果：

[2, 4]

如果 allIds 有 n 项、selectedIds 列表有 m 项，逐项做列表 contains 最坏需要 O(n × m) 次比较。先建 HashSet 的成本约 O(m)，随后在合理哈希假设下整体约 O(n + m)，代价是额外空间。只有一次查找或集合极小时，不一定值得建立索引。

12 · P2：Android 额外认识这些容器

类型常用 API适合优缺点 / 边界
android.util.SparseArray<E>put / get / remove / size() / keyAt / valueAtInt key 到对象的映射避免 Integer key 装箱；基于排序数组，查找约 O(log n)，插入可能移动；get 用 key，keyAt / valueAt 用内部位置
android.util.LongSparseArray<E>put / get / remove / keyAt / valueAtLong key 到对象的映射API 16+；相同思路，不能把它当作 Long 下标的普通 List
SparseIntArray / SparseBooleanArrayput / get / indexOfKey / deleteInt 到 Int / Booleankey 和 value 都避免装箱；默认返回 0 / false，判断是否存在用 indexOfKey >= 0
androidx.collection.ArrayMap / ArraySetput / get / remove；add / contains较小集合、内存更敏感的地方数组结构较紧凑，查找含二分与冲突扫描；写入有搬移，不宜假设总比哈希表快；需 AndroidX Collection 依赖
android.util.LruCache<K, V>get / put / remove / evictAll / sizeOf有容量上限的内存缓存访问顺序淘汰；默认按条数，按字节需覆盖 sizeOf；不是磁盘缓存；多步操作仍需考虑原子性
java.util.concurrent.ConcurrentHashMapget / put / putIfAbsent / compute多个线程共享映射不允许 null key / value；单次 API 的并发保证不自动覆盖先判断后写入；Android 方法可用性取决于 API / 脱糖配置

别直接把“整型 key 就必须 SparseArray”当规则：选择取决于数量、读写比例、内存与平台实现。Compose / StateFlow 场景还要考虑状态发布；普通 MutableList 的原地修改不会自动获得可观察能力。跨协程共享写入可考虑 Mutex 或单一协程持有状态；普通 MutableMap.getOrPut 不保证并发只计算或写入一次。

13 · P1：最容易踩的 6 类坑

① 浅拷贝只复制容器，不复制里面的对象

Kotlin · shallow-copy
data class User(var name: String)
val original = mutableListOf(User("Alice"))
val snapshot = original.toList()
original[0].name = "Bob"
println(snapshot[0].name)
val copiedUsers = original.map { it.copy() }
original[0].name = "Carol"
println(copiedUsers[0].name)

运行结果：

Bob
Bob

这里 User 只有 String 字段，逐项 copy 足够隔离 name 的赋值；如果对象里面还有 MutableList，data class.copy() 仍会共用内部列表。深拷贝要按对象结构决定，不能只多加一个 toList。

② 哈希 key / Set 元素的相等性字段不能随意变化

Kotlin · hash-key
data class Key(var id: Int)
val key = Key(1)
val lookup = hashMapOf(key to "value")
val before = key.hashCode()
key.id = 2
println(before != key.hashCode())
// key 还在旧的哈希位置，后续按新 hashCode 查找可能失败。
// 正确做法：使用稳定的 ID 作为 key。
val stable = hashMapOf(1 to "value")
println(stable[1])

运行结果：

true
value

HashMap / HashSet 先通过 hashCode 缩小查找范围，再通过 equals 判断相等。自定义类若重写 equals，必须让“相等对象 hashCode 相等”；不同对象 hashCode 相同只是碰撞，不代表相等。data class 会根据主构造参数生成这些方法，所以可变主构造字段尤其要谨慎。

③ 遍历期间删除：使用匹配的迭代器，或集合过滤 API

Kotlin · safe-remove
val numbers = mutableListOf(1, 2, 3, 4)
val iterator = numbers.iterator()
while (iterator.hasNext()) {
    if (iterator.next() % 2 == 0) iterator.remove()
}
println(numbers)
numbers.removeAll { it > 1 }
println(numbers)

运行结果：

[1, 3]
[1]

不要在 for (item in list) 里直接 list.remove(item)，这会破坏普通迭代过程，在常见 JVM 集合中可能抛 ConcurrentModificationException。这个异常也能发生在单线程，名字里的 Concurrent 不等于一定有多个线程；不要依赖它必然抛出。

④ plus / minus 返回新集合，循环追加容易反复复制

Kotlin · plus-vs-add
val old = listOf(1, 2)
val updated = old + 3
println(old)
println(updated)
val builder = mutableListOf<Int>()
repeat(3) { builder.add(it) }
println(builder)

运行结果：

[1, 2]
[1, 2, 3]
[0, 1, 2]

循环里 var result = emptyList<Int>(); result = result + x 可能累计 O(n²) 复制。批量构建时可用可变容器，结束后按需要 toList。+= 究竟原地增加还是重赋新集合，受接收者静态类型和操作符解析影响；学习阶段用显式 add 或赋值更清楚。

14 · 串起来：分页数据去重、查找、选中与提交

假设页面已有一批卡片，新一页可能含重复 ID。我们的规则是：首次出现的 ID 决定位置，后到数据更新内容；选中状态按 ID 维护；提交时保持页面顺序。这里用 LinkedHashMap 做合并索引，用 Set 表达选中，用 List 提供展示顺序。

Kotlin · page-merge
data class Card(val id: Long, val title: String)
val current = listOf(Card(1L, "A"), Card(2L, "B-old"))
val nextPage = listOf(Card(2L, "B-new"), Card(3L, "C"))
val byId = linkedMapOf<Long, Card>()
for (card in current) byId[card.id] = card
for (card in nextPage) byId[card.id] = card
val display = byId.values.toList()
println(display.map { it.title })
println(byId[2L]?.title)
val selectedIds = mutableSetOf(1L, 3L)
selectedIds.remove(1L)
val submitted = display.filter { it.id in selectedIds }
println(submitted.map { it.id })

运行结果：

[A, B-new, C]
B-new
[3]

为什么不用 HashMap？我们需要保持位置。为什么不直接 distinctBy？它保留首个 ID 对应的旧内容。为什么选中状态不单纯用 List？这里关心 ID 唯一及包含检查。为什么 values.toList？让展示列表的结构独立于后续 Map 修改；Card 的字段是 val，也让这个示例的元素内容更容易控制。合并过程在合理哈希假设下约 O(n + m)，额外空间与不同 ID 数量有关。

这段只演示容器用法，不含网络请求、线程切换和状态发布。用于 Android UI 时，仍需通过你的 StateFlow / LiveData / Compose 状态机制提交新数据；对 DiffUtil / ListAdapter，保留旧列表和旧元素的稳定内容才能可靠比较，避免先修改旧数据再提交。

15 · 面试自测与官方参考

val 修饰 MutableList，为什么还能 add？

val 限制变量重新绑定，不限制对象内部修改。List 是只读接口，底层对象可能还有可变引用。

Array<Int> 与 IntArray 怎么选？

固定长度纯整数数据可用 IntArray，JVM 下避免泛型元素装箱；需要 nullable 元素等不同语义时再选引用数组。

ArrayList 的增删查复杂度？

随机访问 O(1)，按值查找 O(n)，尾追加均摊 O(1)，中间插删 O(n)。说明操作位置，比笼统说“增删慢”更准确。

保序去重怎么做？

只要第一次出现的元素可 distinct / distinctBy；集合形式可 LinkedHashSet。若同 ID 后者更新内容且保留位置，可显式 LinkedHashMap 合并。

Map.get 返回 null，是不是 key 不存在？

不一定，Map 可能存储 null。需要区分时用 containsKey。

associateBy 和 groupBy 有什么区别？

前者每个 key 对应一个元素，重复时后者覆盖；后者每个 key 对应一组元素。

为什么不一律用 LinkedList？

按下标仍需遍历，节点开销更大；只有已定位节点处修改的链接调整才是 O(1)。栈队列通常可先考虑 ArrayDeque。

Sequence 一定更快吗？

不一定；惰性、短路和减少中间集合可能有收益，小集合和简单操作可能被迭代开销抵消。

toList 和 data class.copy 是深拷贝吗？

不是。前者复制容器结构，后者复制字段值；字段若是可变对象引用仍会共享。

HashMap 能直接用于多线程共享写入吗？

普通 HashMap 不提供这种安全保证。选并发容器或锁 / 单一状态拥有者，同时处理多步逻辑的原子性。
