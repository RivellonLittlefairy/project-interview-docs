01 · 读业务代码必需的语法

React 用组件描述界面，RN 把宿主组件落到原生 UI；View / Text 可以先类比容器和文本控件。RN 不通过浏览器 DOM 显示这些组件。下面只补业务代码常见的语法。

变量、解构和对象更新

const user = {name: '小明', age: 18};
const {name} = user;                 // 取出 user.name
const nextUser = {...user, age: 19}; // 新对象，保留其余字段
const title = response?.title ?? '无标题'; // null/undefined 时用默认值
let count = 0;
count += 1;

const 限制变量重新赋值，不代表对象不可变，类似 Kotlin 的 val 不保证对象内容不可变。... 是浅拷贝，深层对象仍可能共享引用。更新 React 对象状态时应返回新对象，例如 setUser(prev => ({...prev, age: 19}))。

传回调和立即调用，要分开读

const add = (n: number): number => n + 1;

// 点击时才执行
<Button title="保存" onPress={save} />;
<Button title="保存" onPress={() => save(name)} />;

// 常见错误：渲染时就调用 save，把返回值传给 onPress
// <Button title="保存" onPress={save(name)} />

箭头函数是一种 JS 函数写法，可作为参数传递、作为返回值，也可以捕获外层变量。类比 Kotlin 的函数类型即可；Kotlin 的 lambda 与 fun(...) { ... } 匿名函数是不同写法，不必混用术语。

TypeScript、import 和 JSX

import {useState} from 'react';
import {Text} from 'react-native';

type User = {name: string; age?: number}; // age 可以不提供
const [user, setUser] = useState<User | null>(null);

// JSX 花括号里写 JS 表达式；RN 文本放进 Text
<Text>{user?.name ?? '未登录'}</Text>;

这是语法片段，useState 要放进组件或自定义 Hook 中。尖括号里的 User | null 是状态类型；.tsx 支持 TS 与 JSX。TS 类型通常在构建时被移除，不会自动检查接口 JSON；as User 也不是运行时校验。import 表示从模块获取导出的值，遇到陌生组件先跟进它的导入路径。

业务请求还要认识 async / await：async 函数返回 Promise，await 等待结果时暂停该异步函数后续执行，不会阻塞整个 JS 线程，也不自动创建后台线程；失败通常用 try/catch 处理。

02 · 闭包：回调为什么能记住外层变量

闭包并不是什么特殊语法。函数被创建时，会保留访问外围词法作用域的能力；即使外层函数已经返回，内层函数仍然能访问相关变量。

function makeCounter() {
  let count = 0;
  return () => ++count;
}
const next = makeCounter();
console.log(next()); // 1
console.log(next()); // 2：仍能访问那次 makeCounter 调用中的 count

闭包不是一律把值复制冻结。如果修改的是同一个作用域里的变量，闭包可以读到它的变化。React 的旧闭包问题，是因为组件每次重新执行都会产生新一轮局部变量和函数。

// 用普通 JS 模拟“两次调用各有一份局部变量”
function makeHandler(count) {
  return () => count;
}
const oldHandler = makeHandler(0);
const newHandler = makeHandler(1);
console.log(oldHandler()); // 0
console.log(newHandler()); // 1

在 React 中，第一次渲染注册的定时器可能继续持有第一次的回调；后续渲染里的 count 虽然变了，旧回调并不会自动换成新函数。所以 effect 的依赖数组、函数式 state 更新和 ref 都是在处理不同需求下的状态访问问题，不能简单认为“用了闭包就是 bug”。

useCallback(fn, []) 会尝试保留同一个函数引用，但不会神奇地让这个函数读取每次渲染的最新局部变量。要根据真正使用的数据声明依赖，或使用适合该场景的状态访问方式。

03 · props、state 和单向数据流

组件可以先理解成“接收输入、返回 UI 描述的函数”。props 是父组件给的输入，state 是 React 为该组件保存的状态。普通局部变量不等于 state：重新调用组件函数时局部变量会重新建立，修改它也不会自动通知 React 更新。

type CounterButtonProps = {
  count: number;
  onIncrement: () => void;
};

function CounterButton({count, onIncrement}: CounterButtonProps) {
  return (
    <Pressable onPress={onIncrement}>
      <Text>点击次数：{count}</Text>
    </Pressable>
  );
}

function CounterPage() {
  const [count, setCount] = useState(0);
  return (
    <CounterButton
      count={count}
      onIncrement={() => setCount(previous => previous + 1)}
    />
  );
}

数据往下传：CounterPage → count → CounterButton。事件往上传：孩子调用父级传入的 onIncrement。父级更新 state 后，React 重新计算相关 UI，再把新 count 给孩子。这叫单向数据流。

子组件不应直接修改 props。多个兄弟组件需要共享同一份数据时，常把状态放到共同父级，再传给它们，称为“状态提升”。

受控组件指 UI 的显示值由 React 状态控制。例如 <TextInput value={name} onChangeText={setName} />：用户输入通过事件改变 state，state 再决定输入框 value。如果只给 value 却不处理更新，输入框可能一直保持旧值。

04 · Hook：业务开发与常见追问

Hook 是让函数组件使用 React 状态等能力的 API，不是 Android 插桩。这里记住三件事：组件函数会反复执行，React 保存状态，副作用需要建立和清理。

1 · useState：保存的是 React 的状态，count 是本次读取结果

import {useState} from 'react';
import {Button, Text, View} from 'react-native';

export function Counter() {
  const [count, setCount] = useState(0);

  function handlePress() {
    setCount(count + 1);
    console.log('这次回调中的 count:', count);
  }

  return (
    <View>
      <Text>点击次数：{count}</Text>
      <Button title="加 1" onPress={handlePress} />
    </View>
  );
}

先把第一行展开读：useState(0) 返回两个东西，数组解构把它们分别命名为 count 和 setCount。count 是本次渲染读取到的状态值；setCount 是向 React 请求更新该状态的函数。数字 0 是初始状态。

首次渲染
count = 0→点击回调
请求状态变为 1→再次渲染
新的 count = 1→提交更新
文本显示 1
时刻实际执行为什么
首次渲染useState 初始化为 0；创建 handlePress；返回 JSXonPress={handlePress} 只是传函数，没有调用它
第一次点击执行第一轮创建的 handlePress；setCount(0 + 1)该函数捕获的是第一轮的 count
紧接着打印输出 0setter 没有给当前闭包的 count 重新赋值
下一轮渲染React 再调用 Counter；useState 返回状态 1React 保留了该组件身份对应的状态
新界面提交后再点击新 handlePress 读取 1，请求变成 2；打印 1这是新一轮创建的闭包

每次组件调用确实都会新建局部 count。每次调用都有自己的局部 const count，但 useState 给这个新变量的值可以分别是 0、1、2。跨渲染保存的是 React 管理的状态记录，不是某个一直被修改的局部 const。

这里的“状态快照”是指本次渲染读取到的值，并不意味着 React 会深复制或冻结所有对象。不要直接改 state 中的对象。setCount 在同一组件挂载期间具有稳定身份；更新可能被合并，也可能因值相同而跳过，不能按 setter 调用次数推算渲染次数。await setCount(1) 也不能等待界面提交，它不返回这样的 Promise。

2 · 连续累加，用函数式更新

// 假设这次回调里的 count 为 0；两种写法分别看
setCount(count + 1);
setCount(count + 1); // 两次都请求设为 1

// 换成下面的写法，React 按队列计算：0 → 1 → 2
setCount(previous => previous + 1);
setCount(previous => previous + 1);

previous 是 React 提供的待处理状态，不是外层闭包的 count。可以类比 MVI 的“旧状态 → 新状态”更新函数。更新函数只做计算和返回，不在其中请求网络或埋点。

3 · useRef：返回一个对象，帮你在多次渲染之间保存数据

你刚理解了 useState 返回“状态值 + 更新函数”。useRef 更简单：它返回一个对象，对象的 current 属性用来放你要保存的内容。先看返回值，再看它为什么有用。

① useRef(0) 返回什么？

const clicks = useRef(0);

// 第一次拿到的对象可以理解成：
// clicks → {current: 0}

function handlePress() {
  console.log(clicks.current); // 初次点击时，读取到 0
  clicks.current = 5;          // 修改其中的值
  console.log(clicks.current); // 5
}

这是组件中的教学片段，handlePress 作为事件回调使用。clicks 是你取的变量名，current 是 React 约定的属性名。它不是数组，所以不写 const [clicks, setClicks] = useRef(0)；也没有配套 setter，直接给 current 赋值即可。

const clicks 不妨碍修改 clicks.current。可以类比 Kotlin：val box 不允许 box 指向另一个对象，但 box 对象中的 var current 仍然可以修改。

② 和自己写 {current: 0} 有什么区别？

function Example() {
  const ordinary = {current: 0}; // 每次组件执行，都新建一个对象
  const saved = useRef(0);       // React 为同一组件身份保留对象
  // 其他逻辑和 JSX……
}

区别在组件再次执行时。普通对象声明重新执行，就创建新对象；useRef 再次调用时，React 返回先前保留的那个对象。

过程ordinarysaved
第一次组件执行新对象 A，current=0React 保存对象 R，current=0
在事件中把两者的 current 改成 5A.current=5R.current=5
随后因 state 或父级更新，再执行组件创建新对象 B，current 又是 0返回同一个 R，current 仍是 5

局部变量 saved 每次会重新声明，但它拿到的是同一个对象引用。useRef(0) 里的 0 是初始值，不会在每次调用时把 current 重置为 0。这种保留针对同一组件身份；卸载后重新挂载通常会创建新的 ref，它不是全局单例，也不会像 ViewModel 那样自动跨组件卸载保留。

③ 修改 current 后，为什么页面没变化？

保存数据与通知界面更新，是两件事。修改 current 就像修改普通对象字段，不会因此调度 React 渲染。下面是可以放入 RN 工程的完整教学组件：

import {useRef, useState} from 'react';
import {Button, Text, View} from 'react-native';

export function RefDemo() {
  const clicks = useRef(0);
  const [shownCount, setShownCount] = useState(0);

  function recordClick() {
    clicks.current += 1;
    console.log('实际记录的次数：', clicks.current);
  }

  function showCount() {
    setShownCount(clicks.current);
  }

  return (
    <View>
      <Text>上次同步到界面的次数：{shownCount}</Text>
      <Button title="只记录一次" onPress={recordClick} />
      <Button title="把次数显示出来" onPress={showCount} />
    </View>
  );
}
  1. 首次渲染：clicks.current 是 0，shownCount 也是 0，文本显示 0。
  2. 点击“只记录一次”：current 变成 1，控制台打印 1；没有调用状态 setter，文本仍显示 0。
  3. 再点两次：控制台依次打印 2、3，文本仍显示 0。
  4. 点击“把次数显示出来”：把 current 的值 3 交给 setShownCount，React 安排更新。
  5. 组件再次执行：useRef 返回之前的对象，current 仍是 3；useState 返回新的 shownCount=3，文本随后更新为 3。

这个组件故意把“内部记录的数”和“上次显示的数”分开，方便看出差别。如果产品要求每点一次就更新显示，直接用 useState 保存计数更合适，不必同时用两套数据。ref 与 state 不会自动互相同步。

用传统 Android View 理解：你修改 Activity 的一个字段 clickCount++，TextView 的文字不会自己改变；还需要执行 textView.text = ...。ref 类似那份不自动更新 UI 的字段，而 React 的 state setter 会通知框架按新状态重新计算界面。这是职责类比，ref 实际由 React 管理，并不是 Activity 字段。

④ 业务里什么时候该用？

需要保存什么先选什么理由
输入文字、加载状态、页面展示的数量useState变化需要反映到界面
需要跨渲染、供多个回调访问的定时器句柄或订阅对象useRef需要记住它，但修改不必触发 UI 更新
需要调用 focus 等方法的原生组件实例useRef 配合组件 ref 属性通过引用访问组件暴露的方法
只在当前一次计算中用的临时结果普通局部变量不需要跨渲染保存

不是所有句柄都要放 ref：如果定时器只在同一次 effect 的 setup 和 cleanup 里使用，局部变量加闭包已经够了。需要事件回调也能访问它时，再考虑 ref。

“获取输入框并让它获得焦点”很接近 Android 开发经验：

import {useRef} from 'react';
import {Button, TextInput, View} from 'react-native';

export function FocusDemo() {
  const inputRef = useRef<TextInput>(null);

  return (
    <View>
      <TextInput ref={inputRef} placeholder="请输入昵称" />
      <Button
        title="开始输入"
        onPress={() => inputRef.current?.focus()}
      />
    </View>
  );
}

useRef<TextInput>(null) 中的尖括号是 TS 类型，表示这个 ref 用来引用 TextInput；初始 current 为 null。把它传给 ref={inputRef} 后，React 在组件挂载提交时设置引用，在卸载时清空。点击按钮时，通过 current 调用输入框的 focus 方法。

你可以把操作目的类比成 editText.requestFocus()；但 JS 中拿到的是 RN 组件对外暴露的引用，不是任意一个 Java EditText 对象。可调用的方法以 RN 组件接口为准，尚未挂载或已卸载时 current 可能是 null，所以这里使用 ?.。

最后接上闭包：旧回调如果保存的是 clicks 对象，并在执行时读取 clicks.current，就能读到后来写入的内容；如果先取出数字 const savedCount = clicks.current，回调再使用 savedCount，它仍可能是旧数字。不要把 ref 理解成“所有旧闭包都会自动更新”。一般在事件或 effect 中读写 ref，不要靠渲染期间随意修改 current 来驱动 UI。

4 · useEffect：在提交后建立外部同步，并交代怎么收尾

先回答“为什么需要它”：组件函数可能反复执行，渲染也可能被重试或放弃。如果直接在函数体里 setInterval、注册监听或连接服务，每次渲染都可能多建一份。Effect 用于把已经提交的组件数据与 React 之外的系统同步，例如定时器、事件源、网络或原生服务。

以下计时器是可单独阅读的完整教学组件：

import {useEffect, useState} from 'react';
import {Text} from 'react-native';

export function Ticker({intervalMs = 1000}: {intervalMs?: number}) {
  const [ticks, setTicks] = useState(0);

  useEffect(() => {                         // A：setup 建立函数
    const timer = setInterval(() => {      // B：定时回调
      setSeconds(previous => previous + 1);
    }, intervalMs);

    return () => {                          // C：cleanup 清理函数
      clearInterval(timer);
    };
  }, [intervalMs]);

  return <Text>触发次数：{ticks}</Text>;
}

ticks 每次回调加 1，表示触发次数；intervalMs 改变或 JS 忙碌时，不能把它当准确墙上时钟。现在逐个辨认函数：

  1. A 是 setup：组件渲染时把函数传给 useEffect。React 在相应提交后的 effect 阶段执行它，建立一个定时器。
  2. B 是定时回调：由定时器系统稍后调用，每次请求次数加 1；不是 React 每渲染一次就调用一次。
  3. C 是 cleanup：A 把这个函数返回给 React。此时没有执行 clearInterval；React 在需要清理时才调用 C。

return () => clearInterval(timer) 是“返回一个以后负责关定时器的函数”；return clearInterval(timer) 会立刻关掉定时器并返回 undefined，两者含义完全不同。

发生的事setup / cleanup 怎么执行
以 intervalMs=1000 挂载并提交setup A 执行，建立定时器 T1
T1 触发，state 变化并提交组件再次执行，依赖仍为 1000，不重建定时器
父级把 intervalMs 改为 500，新结果提交先调用旧 cleanup 关闭 T1，再运行新 setup 建立 T2
组件卸载调用 T2 对应的 cleanup

旧 cleanup 为什么能找到 T1？timer 是那次 setup 的局部变量，cleanup 通过闭包继续访问它。下一次 setup 创建另一个 timer 和另一个 cleanup，各自对应自己的资源。这就是闭包在资源清理中的用途。

Effect 回调仍运行 JS，不是自动放到后台线程。请求 API 可以异步，但回调里的大计算依然会占用 JS 执行时间。useEffect 也不能作为“用户一定已看到屏幕”的严格时序保证。

不要直接套 Activity 生命周期：[] 的 effect 不是 onResume；RN 页面隐藏可能仍然挂载。需要进入可见状态就恢复播放、隐藏就暂停时，应接入宿主或导航提供的可见性事件。开发环境启用相应 Strict Mode 检查时，还可能额外经历 setup → cleanup → setup；RN 0.72 是否触发具体检查取决于根节点和渲染器配置，不能断言本项目一定“双调用”。资源建立和清理应当能够配对。

5 · 依赖数组：什么时候要重新同步

写法含义
省略第二个参数该组件每次提交后重新执行 effect
[]挂载提交后执行，不因普通依赖变化重跑；卸载清理，开发检查另有边界
[topic]首次执行；topic 变化后先清理旧 effect，再建立新 effect；卸载也清理

依赖由 effect 读取的 props、state 等响应式值决定，不能为“只执行一次”随意删成空数组。React 逐项用 Object.is 比较，不是深比较；每轮新建的对象或函数可能让 effect 反复重跑。

Ticker 不需要把 ticks 放进依赖，因为回调使用函数式更新，没有读取外层 ticks。setTicks 身份稳定，可以省略。需要定时器间隔变化时重新建立，所以依赖是 intervalMs。

6 · 常见坑：定时器一直把 count 设为 1

// 假设首次渲染 count = 0
useEffect(() => {
  const timer = setInterval(() => {
    setCount(count + 1); // 一直读取建立此回调的那轮 count：0
  }, 1000);
  return () => clearInterval(timer);
}, []);

// 对“每次在原数值上加 1”的需求，回调改为：
// setCount(previous => previous + 1);

初次 count=0，空数组保留的定时器一直持有那轮回调，所以反复请求设为 1。改为 setCount(previous => previous + 1) 可以正确累加；但它不会顺便让回调里的其他旧 props 或 console.log(count) 自动变新。

还有两条业务边界：异步请求可能先发后到，切换对象后应忽略旧结果或按 API 能力取消；不要直接写 useEffect(async () => …)，应在 setup 内定义并调用 async 函数，让 setup 能正常返回清理函数。

7 · useCallback / useMemo：知道缓存对象的区别即可

Hook返回什么依赖变化时
useCallback(fn, deps)函数引用返回这一轮的新函数，不调用它
useMemo(calculate, deps)计算结果在渲染期间重新计算

两者都是缓存优化，不会创建后台线程，也不会自动修复旧闭包。useCallback 不阻止新函数被创建；依赖没变时，React 返回缓存的旧函数。只有消费者需要稳定引用或计算确有成本时再用。

项目实例：头像点击。pikachu/pages/VipPin/src/components/NavBar/Avatar.tsx，66 行附近：

const onPress = useCallback(() => {
  if (jumpUrl) {
    void ZRouter.openURL(jumpUrl)
  }
}, [jumpUrl])

jumpUrl 变化时得到读取新地址的回调；改成 [] 可能一直打开旧地址。同文件把 onPress 传给点击组件，useCallback 本身不会打开页面。依赖数组是缓存更新条件，不是闭包捕获列表。

8 · 项目里的状态更新，以及 Hook 调用规则

pikachu/pages/VipPin/src/PinIndex.tsx，115 行附近：

const handleFollowStatusChange = useCallback((isFollowing: boolean) => {
  setPageData(prev => ({
    ...prev,
    info: {
      ...prev.info,
      isFollow: isFollowing,
    },
  }))
}, [])

业务调用传入 isFollowing，React 调用内层更新函数时提供 prev。这里没有捕获外层 pageData，setPageData 又是稳定函数，因此空依赖有依据。它创建新的 pageData 和 info，保留其他字段。

调用规则：Hook 要放在组件或自定义 Hook 顶层，不放在 if、循环或普通事件回调里，也不放在可能提前 return 之后。React 依赖稳定调用顺序匹配状态；事件里调用 setter 可以，临时调用 useState 创建状态不行。

自定义 Hook：把一组状态和同步逻辑抽成 useXxx 函数。它复用逻辑，不自动共用状态；两处调用内部的 useState 各自保存状态，除非显式连接同一共享数据源。

05 · 列表、key 与基本布局

map 把每个元素转换成一个新结果，组成新数组；filter 留下满足条件的元素。它们不会自动深复制数组里的对象。

const items = [{id: 'a', title: '第一项'}, {id: 'b', title: '第二项'}];
const titles = items.map(item => item.title);    // ['第一项', '第二项']
const kept = items.filter(item => item.id !== 'a'); // 只保留第二项

// JSX 中，小列表可以这样显示；长列表通常用 FlatList 等组件
<View>
  {items.map(item => <Text key={item.id}>{item.title}</Text>)}
</View>

key 让 React 判断更新前后同级条目是否仍是同一个条目。优先使用稳定的业务 ID，不要每次生成随机数，也不要在会重排的列表里轻率地使用数组位置。它不是普通 props；孩子需要 ID 时，要另传 id={item.id}。

// 更新一个条目：创建新数组，变化的条目创建新对象
setItems(previous => previous.map(item =>
  item.id === targetId ? {...item, title: '新标题'} : item
));

// 删除一个条目
setItems(previous => previous.filter(item => item.id !== targetId));

// 添加一个条目
setItems(previous => [...previous, newItem]);

这样的写法保留未变化条目的引用，为变化的数据创建新引用，便于 React 和相关优化判断更新。不是“只要创建新对象就快”；如果每次无意义地创建所有 props 对象，也可能让 memo 的浅比较失效。

布局只先记住这几条

RN 使用 JS 样式对象；flexDirection 默认 column，row 表示横向。justifyContent 控制主轴分配，alignItems 控制交叉轴对齐。普通尺寸使用逻辑单位数值，如 padding: 16；style 数组中后面的有效同名属性覆盖前面的。

06 · 一个输入框页面，把知识串起来

下面是一个完整的教学 TSX 组件文件：输入框、按钮和状态都在本地，不需要网络。它仍需放到已配置的 RN 工程中使用；本文没有把它注册或运行成独立 App。

import {useState} from 'react';
import {Button, Text, TextInput, View} from 'react-native';

type NameCardProps = {
  initialName?: string;
  onSave: (name: string) => void;
};

export default function NameCard({
  initialName = '',
  onSave,
}: NameCardProps) {
  const [name, setName] = useState(initialName);
  const trimmed = name.trim();

  return (
    <View style={{padding: 16}}>
      <Text>昵称：{trimmed || '未填写'}</Text>
      <TextInput
        value={name}
        onChangeText={setName}
        placeholder="请输入昵称"
      />
      <Button
        title="保存"
        disabled={trimmed.length === 0}
        onPress={() => onSave(trimmed)}
      />
    </View>
  );
}
  1. import：从 React 获取状态 Hook，从 RN 获取原生 UI 组件接口。
  2. NameCardProps：声明初始昵称可以不传，保存回调必须传。
  3. 函数参数解构：从 props 取出字段，未传 initialName 时使用空字符串。默认值针对 undefined，不是任意空值。
  4. [name, setName]：从 useState 返回的二元组中，取出当前状态和更新函数。
  5. value={name}：让输入框显示由状态控制的值。
  6. onChangeText={setName}：把更新函数作为回调，输入变化后请求更新状态。
  7. onPress={() => onSave(trimmed)}：点击时才通知父级保存，渲染期间不会调用保存。
  8. 下一次渲染重新计算 trimmed 和 JSX；RN 随后完成必要的原生界面更新。

注意初始值边界：组件已经挂载后，父级改变 initialName，不会让这个 useState 自动重置。你需要根据产品语义决定由父级完全控制输入，还是明确同步、重置。这个例子也没有声称 onSave 返回就意味着远端保存成功。

回头再读项目代码：const {vip_pin_id: pinId} = props 是解构重命名；useState<PageDataType>(…) 是带类型的状态；useCallback(() => …, [store, pinId]) 是按依赖缓存函数引用；<Text>{title}</Text> 是将表达式放进 JSX。先把语法读顺，再跟进每个函数的具体实现。

07 · 面试准备：能回答这 5 个问题即可

准备一个自己做过的 RN 功能，能讲清“页面状态 → 用户操作 → 请求或原生调用 → 结果回传 → 监听清理”。以下 5 个问题能结合代码回答，就完成本文的学习目标。

  1. props 和 state 分别由谁提供？状态变化后，组件函数和原生 View 分别发生什么？
