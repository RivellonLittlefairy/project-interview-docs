3. 模块、分层与核心抽象

模块：app（示例）、mercury-core（内核）。

  • H5Page/H5Session 把页面生命周期与 WebView 具体实现隔离
  • JsBridge 用 ConcurrentHashMap 关联请求与回调，并统一 evaluateJavascript 回传
  • WebViewLruCache/H5PageLruCache 降低冷启动，但复用前必须有完整 reset contract

分层判断来自 settings.gradle、模块构建脚本以及下列源码入口的交叉核对；README 只作线索。

4. 初始化与真实业务接入入口

Mercury 的 WebViewFragment2 创建 H5Page；核心的 H5PageImpl 再创建 IZhihuWebView、绑定 bridge/client 和资源策略。

接入责任边界：业务侧需要负责参数映射、页面/会话生命周期、错误态与降级、埋点和真实场景验证；基础库内部机制能解释问题，但不能据此宣称自己是框架作者。

5. 关键调用链

H5PageImpl → 创建 IZhihuWebView → addJavascriptInterface(JsBridge) → H5WebViewClient/ResourceLoader → JsBridge 以 event map 关联回调 → evaluateJavascript 返回 H5

复述时建议按“业务入口 → 稳定抽象 → 实现/策略 → 系统或三方边界 → 状态回传”展开，这样能明确自己在调用侧做了什么，也能说明故障应在哪一层定位。

6. 核心机制、亮点与取舍

  • H5Page/H5Session 把页面生命周期与 WebView 具体实现隔离
  • JsBridge 用 ConcurrentHashMap 关联请求与回调，并统一 evaluateJavascript 回传
  • WebViewLruCache/H5PageLruCache 降低冷启动，但复用前必须有完整 reset contract

取舍结论：统一封装提高复用、可替换性和观测一致性，但会把配置、生命周期、并发或兼容性问题集中到公共层。因此接入不能只验证 happy path。

7. 风险、兼容性与调试路径

主要风险

  • addJavascriptInterface 是高风险权限边界
  • LRU 复用可能污染 WebSettings、history、cookie、client 和 JS interface
  • 同步资源拦截会阻塞 WebView IO 线程，回调 map 也可能泄漏

建议调试顺序

  1. 桥接问题用 event name/request id 对齐 JS 与 native
  2. 复用问题对比新建和命中缓存后的 WebView 状态
  3. 资源问题记录 RequestPolicy 决策、缓存命中和网络 fallback

涉及 Android 版本、OEM、系统组件或三方 SDK 的路径，应补真机矩阵；涉及缓存、并发和生命周期的路径，应同时保留会话 id、时间线和线程信息。
