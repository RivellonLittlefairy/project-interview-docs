1. 仓库定位与面试边界

yyyyy-cdoe/VipPassport 的当前定位是登录注册、验证码、第三方绑定与 Token 管理组件。主要技术形态为 Kotlin/Java、ViewModel/LiveData、Repository、RxJava/Retrofit 与第三方登录 SDK。

面试应聚焦业务入口、状态编排、生命周期、异常兜底和组件集成。可以讲“我如何使用既有能力完成业务调用与排障”，但“本人实现/主导”的范围一律需本人确认，且应有 MR、commit、需求、评审或上线记录佐证。

5. 关键调用链与边界

源码直接链路：账号注册

  1. RegisterFragment 收集手机号、验证码或社交注册输入
  2. RegisterViewModel 调用 RegisterRepositoryImpl
  3. RegisterRepositoryImpl 调 RegisterRemoteDataSource
  4. RegisterRemoteDataSource 调 AccountRegisterService
  5. 结果回到 ViewModel/Fragment 更新注册状态

边界说明：Token 持久化、头像上传和社交绑定属于注册成功后的后置链，不应省略 RemoteDataSource 直接跳到 Service。

6. 技术亮点与取舍

亮点

多来源注册统一成表单模型，风控预处理、验证码、账号创建与后置绑定边界清楚。

取舍

统一流程减少重复，但三方回调、Token 安全、Activity 重建与注册后部分失败更难恢复。

面试时不要把“使用了某框架”本身当亮点。更有价值的是说清楚为什么这样划分状态与生命周期、失败如何降级、版本/协议如何兼容，以及出现竞态时如何用真实调用链定位。

7. 仓库专属风险与排查顺序

下面的顺序按本仓真实状态 owner、服务与生命周期组织；前一步没有证据时，不跳到渲染层猜测。

  1. 第 1 步。先核对 RegisterFragment 的注册类型、区号、手机号、验证码和 callback 参数。
  2. 第 2 步。检查 RegisterViewModel 当前请求状态，防止重复点击产生并发注册。
  3. 第 3 步。沿 RegisterRepositoryImpl → RegisterRemoteDataSource → AccountRegisterService 检查参数转换与错误码。
  4. 第 4 步。账号已创建但后置步骤失败时保存服务端账号真值，把 Token、头像或绑定按可恢复任务处理。

8. 可直接复述的讲法

30 秒版本

VipPassport 的注册链不能跳过数据源：RegisterFragment → RegisterViewModel → RegisterRepositoryImpl → RegisterRemoteDataSource → AccountRegisterService。账号创建成功后，Token、头像和社交绑定是可恢复后置步骤，不应和核心注册事务混为一谈。 个人参与范围需本人确认。

2 分钟版本

用户输入先由 RegisterFragment 校验，RegisterViewModel 组织请求，RepositoryImpl 把远端职责交给 RegisterRemoteDataSource，后者才调用 AccountRegisterService。服务端创建账号成功后，再处理 Token 持久化、头像上传或社交绑定。显式 RemoteDataSource 让仓储可扩展缓存和 fake，但层级增加，错误必须保留原始业务码，后置失败也不能把已成功注册误报成整体失败。 若要把其中某个调用点写成个人成果，仍需本人确认并提供可核验记录。

9. 仓库专属追问与回答

1. 问：Repository 会直接调用 AccountRegisterService 吗？

答：正确链中还有 RegisterRemoteDataSource，RepositoryImpl 把远端请求委托给它。

2. 问：头像上传失败要回滚账号吗？

答：通常不应把可恢复后置步骤等同核心注册失败，应保存账号真值并提供重试。

3. 问：如何避免重复注册请求？

答：ViewModel 维护提交中状态，并以手机号/注册方式和请求 id 约束重复点击及旧回调。

4. 问：最小测试覆盖哪些层？

答：Repository 用 fake RemoteDataSource，RemoteDataSource 用 fake Service，页面测试重复提交和错误展示。

5. 问：面试中怎样说明自己在这个仓库里的贡献边界？

答：只陈述自己能用需求单、MR、commit 或评审记录证明的 vippassport 调用点；公共框架、团队装配体系和历史代码不据为己有。无法核验的个人动作、结果和指标统一标为“需本人确认”。
