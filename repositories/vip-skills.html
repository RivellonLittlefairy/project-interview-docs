VIP-Skills：团队 Agent 工作流仓

定位标签：团队知识资产 / 不是个人项目

定位与归属边界

  • 把项目分析、加调试日志、App 图标提示、发版和 Xcode 构建流程编码为 Agent Skills。
  • 这是团队知识资产，不能把全仓成果归为个人；本人负责的 skill、安装器或落地指标需本人确认。
  • 当前有 5 个有效 SKILL.md；空目录不算已实现能力。

检出与构建信息

  • 库存记录：分支 master，提交 cae175f（2026-03-17），Markdown/Shell 配置仓。
  • 入口：install-skills.sh 扫描带 SKILL.md 的目录，交互选择 skill 和 Claude/Cursor/Kiro 目标，再建立全局符号链接。
  • 无传统构建；未检出 skill lint、fixture、snapshot 或安装器测试。本轮未执行安装脚本，避免覆盖用户全局技能目录。

结构与核心入口

  • SKILL_GUIDE.md：技能创建规范。
  • analyze-project/SKILL.md、add-debugs/SKILL.md：分析与日志工作流。
  • release-new-version/SKILL.md、xcode-build/SKILL.md：发布与构建高风险流程。
  • app-icon-prompt/SKILL.md：从产品、平台和品牌生成图标方案。

关键工作流

  1. metadata 描述触发边界 → Agent 检查前置条件 → 生成计划/预览 → 用户确认危险动作 → 执行 → 验证。
  2. analyze-project 先读现有文档，再扫描结构/入口/业务并生成索引。
  3. release skill 检查 Git、识别项目、更新版本/文档，再分级处理 commit/tag/push/publish。
  4. 安装器扫描 skill，选择目标后建立符号链接，使多 Agent 复用同一事实源。

亮点与取舍

  • 把隐性经验变成可发现、可复用流程；metadata 能限制触发边界。
  • 符号链接保持单一事实源，但跨平台和目标目录冲突处理更复杂。
  • 文本技能迭代快，却会随 Agent 工具名/命令变化而漂移。

风险、测试与排查

  • 安装器会递归删除目标 skill 目录后建链接，缺备份、归属校验和冲突预览，是高风险覆盖操作。
  • release skill 涉及 commit/tag/push/publish，必须拆成读检查、用户确认、可逆本地变更、外部发布。
  • add-debugs 应禁止敏感字段日志化；analyze-project 默认排除凭据/二进制；xcode-build 输出应脱敏签名身份。
  • 排查：触发是否正确 → 前置检查 → 写入范围 → 危险动作确认 → 命令兼容 → 最终产物/测试 → 外部发布状态。

Skill 回归矩阵与安装回滚

analyze-project 可用 Android、Node、Python 三个小型 fixture 仓验收：已有文档时先读取，扫描时排除 .git、build、二进制与凭据，输出必须链接真实入口且不虚构业务。add-debugs 则准备同步函数、协程、网络异常和状态变更样例，断言日志位于入口/出口/失败边界，不改变返回值与异常语义；fixture 中放置 token、Cookie、手机号和签名信息，确保 denylist 会阻止其进入日志。

release-new-version 需要完整的危险动作阶梯测试。脏工作树、未知项目类型、版本冲突和测试失败时应在本地阶段停止；版本文件与 README diff 由用户确认后才能 commit，tag、push、publish 必须再次独立确认。使用本地 bare remote 和假 registry 验证重复 tag、push 被拒、publish 超时与回滚说明。任何一次授权都不能默认覆盖后续外部动作。xcode-build 的 fixture 覆盖只有 project、同时存在 workspace、多个 scheme、无设备和签名失败，并确保输出不泄露证书路径或身份详情。

安装器应先枚举真正含 SKILL.md 的源目录和目标 Agent 根，生成“新建、链接已一致、目标冲突、非本工具管理”预览。对冲突目录默认停止；若用户确认替换，先移动到带时间戳的备份，再在同一文件系统创建临时链接并原子换入，失败就恢复。测试在临时目录执行，覆盖路径含空格、断链、无权限、重复运行和部分失败，绝不能操作真实全局技能目录。卸载也只删除由 manifest 记录的链接，不递归删除未知目录。

文本技能的兼容性不能靠人工通读。可以解析 frontmatter 检查 name/description，扫描已弃用工具名和危险命令，使用 snapshot 比较关键步骤，再在支持的 Agent 版本上运行 fixture。采用指标应区分触发正确率、任务成功率、需人工回滚率和节省时间；没有调用日志与样本时，只能说流程被编码，不能宣称团队效率提升。

面试讲法

30 秒版本

VIP-Skills 是团队 Agent 工作流仓，把分析、日志、发版和 Xcode 构建等经验编码为触发、检查、执行与验证步骤。亮点是可复用，风险是安装器覆盖目标目录且缺回归，高风险发布动作也需分级授权。个人贡献需本人确认。

2 分钟版本

这个仓的价值是把隐性工程经验做成 Agent 可发现的 workflow。SKILL_GUIDE 约束结构，五个 skill 覆盖分析、debug、图标、发版和 Xcode；安装器通过符号链接让多 IDE 共用。问题是文本和工具版本会漂移，安装器先删目标目录却没有备份和冲突预览，release 又可能一路做 tag/push/publish。重做会加 fixture、snapshot、dry-run、危险动作审批层级和安装回滚。没有本人 commit/评审与采用指标时，只讲团队设计。

追问与回答

问题1：怎么测试一个 Skill？

用代表性小仓 fixture，断言触发、计划、写入范围、危险确认和验证；文本做结构规则/snapshot，外部动作 mock。

问题2：安装器为什么高风险？

递归删除目标目录可能覆盖用户内容；需要归属校验、diff 预览、备份与原子回滚。

问题3：为什么发布动作要分级？

本地版本修改可逆，push/publish 影响外部协作者；授权范围和失败恢复不同。

问题4：如何防日志 skill 泄密？

维护敏感字段 denylist/结构化脱敏，禁止 token、Cookie、个人数据和签名信息进入日志。

问题5：怎样证明 skill 有价值？

记录真实调用成功率、节省时间、人工回滚率和用户反馈，并注明统计期、样本和来源。
