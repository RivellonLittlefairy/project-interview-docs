1. 仓库定位与面试边界

yyyyy-cdoe/VipMercury 的当前定位是VIP 产品的 WebView/Hybrid 容器、插件与离线资源组件。主要技术形态为 Java/Kotlin、H5Page/JSBridge、可组合 WebViewClient、DNS/离线资源与页面缓存。

面试应聚焦业务入口、状态编排、生命周期、异常兜底和组件集成。可以讲“我如何使用既有能力完成业务调用与排障”，但“本人实现/主导”的范围一律需本人确认，且应有 MR、commit、需求、评审或上线记录佐证。

5. 关键调用链与边界

源码直接链路：Fragment 页面生命周期

  1. WebViewFragment2 尝试从 H5PageCacheManager 获取可复用 H5Page，否则创建页面
  2. onViewCreated 创建 InnerWebClient 并调用 mPage.setWebClient
  3. Fragment 调 loadUrl，内部直接 mPage.loadUrl
  4. 销毁时按缓存与新生命周期规则清理或移除页面

边界说明：H5Page 类型来自 mercury-api；具体 Bridge/插件实现不能仅凭 Fragment 引用全部推导。

独立卡片链

  1. HybridCard.Builder 接收可选 IZhihuWebViewClient/H5Plugin 等
  2. build 创建 HybridCard
  3. HybridCard.load 调 mPage.loadUrl

边界说明：HybridCard 不是 WebViewFragment2 每次加载的中间节点。

独立 DNS client 链

  1. HtmlDnsWebViewClient.shouldInterceptRequest 先调用 super
  2. 符合主文档请求条件时构建 ResourceRequest
  3. 交给 ResourceProvider.requestMainFrame/syncRequestMainFrame

边界说明：只有页面实际装配该 client 时，这条资源拦截链才参与。

6. 技术亮点与取舍

亮点

页面、Bridge、资源 client 和产品插件分层，VIP 差异通过可组合 client/Provider 表达。

取舍

Hybrid 迭代快且能力可复用，但 origin 权限、回调清理、WebView 复用污染和分支安全修复漂移风险高。

面试时不要把“使用了某框架”本身当亮点。更有价值的是说清楚为什么这样划分状态与生命周期、失败如何降级、版本/协议如何兼容，以及出现竞态时如何用真实调用链定位。

7. 仓库专属风险与排查顺序

下面的顺序按本仓真实状态 owner、服务与生命周期组织；前一步没有证据时，不跳到渲染层猜测。

  1. 第 1 步。页面串内容先查 H5PageCacheManager 的 URL、appId、webViewType、pageId 和 useNewApi 复用条件。
  2. 第 2 步。Fragment 白屏从 mPage、InnerWebClient、setWebClient 到 loadUrl/mPage.loadUrl 逐步确认。
  3. 第 3 步。卡片问题只沿 HybridCard.Builder/build/load 查，不把 Fragment 生命周期套进卡片。
  4. 第 4 步。HTML 主文档异常再确认是否实际使用 HtmlDnsWebViewClient，并检查 shouldInterceptRequest 与 ResourceProvider 返回。

8. 可直接复述的讲法

30 秒版本

VipMercury 有三条可验证机制：WebViewFragment2 复用或创建 H5Page、绑定 InnerWebClient 后 loadUrl；HybridCard.Builder 是独立卡片容器；HtmlDnsWebViewClient 只在被装配时拦截主文档请求。三者可组合，但不是固定一条链。 个人参与范围需本人确认。

2 分钟版本

WebViewFragment2 先通过 H5PageCacheManager 判断能否复用页面，onViewCreated 再创建 InnerWebClient、setWebClient，并通过 mPage.loadUrl 加载；销毁阶段还要避免复用已销毁 page。HybridCard 有自己的 Builder/build/load 生命周期。HtmlDnsWebViewClient 则在 shouldInterceptRequest 中按条件把主文档交给 ResourceProvider。Hybrid 复用提升性能，但 URL 与参数复用、Client 组合和 Context 清理任何一处不严谨都会造成串页或泄漏。 若要把其中某个调用点写成个人成果，仍需本人确认并提供可核验记录。

9. 仓库专属追问与回答

1. 问：H5Page 缓存只按 URL 复用吗？

答：不只，H5PageCacheManager 还比较 appId、webViewType、pageId、useNewApi、geoPermissions 等参数。

2. 问：HybridCard 是 WebViewFragment2 的下一步吗？

答：不是，它是独立容器，自己通过 Builder 组合 client/plugin 并 load。

3. 问：HtmlDnsWebViewClient 一定参与所有页面吗？

答：不一定，只有页面实际装配它且请求满足条件时才拦截。

4. 问：怎样测试缓存复用安全？

答：覆盖同 URL 不同 appId/pageId/webViewType 的拒绝复用，以及 destroy 后缓存移除和 Context 解绑。

5. 问：面试中怎样说明自己在这个仓库里的贡献边界？

答：只陈述自己能用需求单、MR、commit 或评审记录证明的 vipmercury 调用点；公共框架、团队装配体系和历史代码不据为己有。无法核验的个人动作、结果和指标统一标为“需本人确认”。
