1. 仓库定位与面试边界

yyyyy-cdoe/VipPrerender 的当前定位是会员内容页面的数据/原生预渲染与命中上报组件。主要技术形态为 Kotlin/Java、Action Receiver、预加载 DataSource、缓存状态与命中 Reporter。

面试应聚焦业务入口、状态编排、生命周期、异常兜底和组件集成。可以讲“我如何使用既有能力完成业务调用与排障”，但“本人实现/主导”的范围一律需本人确认，且应有 MR、commit、需求、评审或上线记录佐证。

5. 关键调用链与边界

源码直接链路：Web 数据预载

  1. DataManager.preload 调用 PrerenderService
  2. 服务结果由 DataCache.put 写入缓存

边界说明：这是数据准备链。

源码直接链路：Web 页面领取

  1. PrerenderHelper 通过 HybridPrerenderInterface 进入 PrerenderSupervisor
  2. Supervisor 交给 PageManager
  3. PageManager 从 DataManager.getCache 取数据
  4. 缓存与页面状态交给 PageHolder

边界说明：PageHolder 实现 LoadActionReceiver；它属于 Web Page 管理，不是 NativePreload 的 receiver。

独立 Native 链

  1. NativePreload 选择 INativeDataLoader
  2. INativeDataLoader 执行原生数据加载

边界说明：Native 路径与 Web 的 PageManager/PageHolder 不应混接。

6. 技术亮点与取舍

亮点

把预测—加载—缓存—消费—上报组成独立闭环，而不是只做一个无观测的预请求。

取舍

命中时可缩短首屏等待，但未消费预载会浪费流量和内存，还可能缓存过期会员态。

面试时不要把“使用了某框架”本身当亮点。更有价值的是说清楚为什么这样划分状态与生命周期、失败如何降级、版本/协议如何兼容，以及出现竞态时如何用真实调用链定位。

7. 仓库专属风险与排查顺序

下面的顺序按本仓真实状态 owner、服务与生命周期组织；前一步没有证据时，不跳到渲染层猜测。

  1. 第 1 步。预载未发起先看 DataManager.preload 的 key、策略与 PrerenderService 请求。
  2. 第 2 步。服务成功但页面未命中时比较 DataCache.put 与 DataManager.getCache 的 key、有效期和消费时机。
  3. 第 3 步。Web 页面领取沿 PrerenderHelper → Supervisor → PageManager → PageHolder 检查。
  4. 第 4 步。原生预载只看 NativePreload 选择的 INativeDataLoader，不去 PageHolder 查 LoadActionReceiver。

8. 可直接复述的讲法

30 秒版本

VipPrerender 要拆成三条链：DataManager.preload → PrerenderService → DataCache.put 准备 Web 数据；页面通过 PrerenderHelper、Supervisor、PageManager 从缓存交给 PageHolder；NativePreload 则只委托 INativeDataLoader。PageHolder 才是 LoadActionReceiver。 个人参与范围需本人确认。

2 分钟版本

Web 预载由 DataManager.preload 调 PrerenderService，成功后 DataCache.put。真正页面到来时，PrerenderHelper 经 HybridPrerenderInterface 和 PrerenderSupervisor 进入 PageManager，再用 DataManager.getCache 把数据交给 PageHolder。PageHolder 实现 LoadActionReceiver。原生路径另由 NativePreload 选择 INativeDataLoader。预渲染能提前隐藏延迟，但 key、过期和一次性消费不一致会造成错页，因此命中日志必须贯穿预载和领取。 若要把其中某个调用点写成个人成果，仍需本人确认并提供可核验记录。

9. 仓库专属追问与回答

1. 问：LoadActionReceiver 由 NativePreload 实现吗？

答：不是，已核对的实现者是 PageHolder。

2. 问：Web 预载数据在哪里写缓存？

答：DataManager.preload 调 PrerenderService 后由 DataCache.put 保存。

3. 问：Native 路径为什么不经过 PageManager？

答：NativePreload 直接选择 INativeDataLoader，是独立原生加载机制。

4. 问：怎样验证预载没有串页？

答：用业务 key、页面 URL/参数和一次性消费标记做契约测试，并覆盖过期、取消与并发领取。

5. 问：面试中怎样说明自己在这个仓库里的贡献边界？

答：只陈述自己能用需求单、MR、commit 或评审记录证明的 vipprerender 调用点；公共框架、团队装配体系和历史代码不据为己有。无法核验的个人动作、结果和指标统一标为“需本人确认”。
